# Acceptance scenarios — Part 7, Price, ledger and audit

✅ ** Approved**: agent-written (ADR-353); the user approves.

← [Acceptance scenarios](README.md) · The part page: [Part 7 — Price, ledger & audit](../parts/07-pricing-ledger-audit.md)

> Each scenario restates a recorded rule; **From** names it. Values are the example world's
> (`spec/CONVENTIONS.md` §6), the golden mission's (`spec/golden/MISSION.md` §1…§4, its rates
> included) and `spec/RULES.md` §9's worked examples. A flag's message is `spec/FLAGS.md`'s, word
> for word. How to read the columns: [README](README.md).
>
> **This file is about what a ticket is worth and how that is kept**: which rules may run on it,
> which pass, what their actions write, each line's quantity, rate and amount, the ledger's lines
> written again when a ticket changes, and the audit log behind all of it. What a rule *is* and
> what setup refuses or warns of is Part 1's file (AC-01-39…51, 60…68, 81); the setup check and
> what each site's phones ask for are AC-01-69…77 (task 1.6.4). The quantities themselves (a
> load's CY, a split's shares, a tandem's weight) are Part 6's (AC-06-73…84); here only which one
> a line bills. What a reviewer does (correct, void, accept, QC, lock) is Parts 8 and 9's (task
> 1.8.1): here only what the worker does to the lines when the ticket comes back.

**Where each scenario is proven.**

| Mark in **Proven at** | Meaning |
|---|---|
| **domain (1.6.2)** | `packages/domain`, no database: which rules may run, and each criterion |
| **domain (1.6.3)** | `packages/domain`: actions to lines, the quantity, the rate, the pricing flags |

| **story (1.7.2)** | The scenario harness: the worker prices, regenerates and audits |
| **database (built, Phase 0)** | Phase 0 built the guard (ADR-270…276) and the test named proves it; the test takes this file's ID with task 1.7.1, and **Passing** is filled from that run |
| **1.8.x** · **story (1.9.1)** | A reviewer's action (Milestone 1.8); the golden mission, whole |
| **back office (Phase 4)** | The rule is recorded; nothing in Phase 1 builds its screen |

**Throughout:** the firm's setup decides which price a contract means; Open ADMS never chooses
(ADR-197, 202). Rates live only on pay items (invariant 7). Only the worker writes a transaction,
as the system actor, and no person edits one (invariant 21). `COMPLETED` and `MANUAL_REVIEW`
tickets both bill wherever an amount can be computed (ADR-060). **The rules of P1 are the golden
mission's §1 unless a scenario says otherwise**, each naming "Coastline, Bayline ROW 2026".
