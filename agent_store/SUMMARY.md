### The database's guards — ARCHITECTURE §5; `adms-verify`'s schema and database pages [094, 097, 113, 270…273, 276]
- **The database enforces the rules itself; no business logic in it.** It holds only guards, each its own reviewed, tested migration: per-service roles and least-privilege grants (column-level on evidence: the API corrects captured columns, the worker writes only `status`, `reconciled_at`); delete and truncate refused for everyone; audit by trigger; `AuditRecord` append-only; a transaction's delete copied to audit first and refused on an invoice-locked load; row-level security with `viewer_*` views, fail closed. [097, 113, 270]
- **Never edit a generated or applied migration**; a guard is written only into Prisma's empty `--create-only` stub (the hook allows nothing else), and a test checks each `migration.sql` against Prisma's recorded checksum. A stub that comes out non-empty means a `dbgenerated` default Prisma reads back differently: fix that (defaults use `transaction_timestamp()`), never write around the hook. [113, 276, KD-70]
- **Every service write goes through `db.$write(actor, (tx) => …)`** (`packages/db`): one transaction whose first statement states `adms.actor_id` and `adms.source` (required) and, when known, device, reason and request, as transaction-local settings; a write outside it states no actor and is refused. Ids are UUIDv7 made by the database (a field event's by the phone); every foreign key `RESTRICT`. [268, 270, 273]
- **A new table is guarded in one line:** its model in the right `.prisma` file, then a guard migration `SELECT guard_table('<table>', '<CONFIGURATION|MARK|EVIDENCE|DERIVED>', '<domain>'[, ARRAY[<worker columns>]]);` (rerun when an evidence model gains a column); a list: `guard_list('<table>', '<domain>')`; a viewer's sight: `guard_viewer(...)` (People, permissions and viewers). The installer stops while `guard_gaps()` lists any unguarded table (it asks what each trigger fires on). [271, 272, 302, 315]
- **The audit capture can leave named columns out** (`audit_capture('SECURITY', 'hash')`: the record says the column changed, never its value): the path for every hash and secret. [281]
- **The system actor:** `User` role `SYSTEM` (never a login), id `00000000-0000-7000-8000-000000000001` in every installation, "Open ADMS (system)", seeded by the installer, which stops if it finds it changed. **Only `adms_worker` (and `adms_owner`'s seed) may write as it** or with source `SYSTEM`; only `adms_owner` changes its row or grants the role. It is never assigned, never on the board, never records a field event, has no employer. *Agent defaults.* [273, 276, 281]
- **The database tests** (`packages/db/test`) run as the stack's administrator with `SET LOCAL ROLE`, each test rolled back on a fresh example world; they read every grant, trigger, check and policy exactly and try each write as each login; a loosened guard must be caught. Try loosened guards two at a time on this 8 GB Docker disk, each copy `STRATEGY FILE_COPY` then `CHECKPOINT` after its drop. [272, 313]

### The installer and the local stack — ARCHITECTURE §4, §14; `NEXT.md` "Tools and housekeeping" [263…266, 268, 517, 525, 565]
- **The local stack:** `infra/local`, one compose project: `pnpm local:up` / `local:down` / `local:wipe` / `local:status`. Postgres, SeaweedFS (S3), Caddy with the stack's own root on `*.adms.localhost` (`https://adms.localhost/health`; `s3.`, `mail.`), Mailpit, the address server (Nominatim), Valhalla, then the API and the worker as containers. Every image pinned by tag and digest; every port on 127.0.0.1 (Postgres on 55432); plain HTTP redirected; dev passwords generated into the git-ignored `infra/local/.env` (0600), handed to containers as files, never printed. `down` keeps data; `wipe` makes the next run a first run. **The stack is stopped at every close-out.** [264, 277]
- **Every hop is encrypted** (the user, ADR-513): `local:up` makes the stack's root and a certificate per service (`infra/local/src/certificates.ts`) into `infra/local/.generated/`; Caddy issues from that root and reaches every service over TLS (`upstream_tls`, checked against the service's one name). The API serves HTTPS alone; Postgres takes TLS alone (`hostssl`), every login's URL `sslmode=verify-full` with the root (`ADMS_DATABASE_CA_FILE` in a container), Prisma's schema engine `require` + `sslcert` + `sslaccept=strict` (`packages/db/prisma.url.js`); mail requires TLS to every server, the catcher included. **Only a container's own loopback is plain** (*agent default*). Valhalla listens on its loopback behind `routing-tls`; **SeaweedFS runs as `weed server`, every part bound to its loopback, S3 reached only through `objectstore-tls`** (`X-Forwarded-Host` believed from the stack's proxy alone). [513, 517, 525]
- **Every container is hardened:** no capability, read-only root, unprivileged user, no new privileges, a digest; three departures named and held by `infra/local/test/compose.test.ts` (Caddy's binary's file capability, never held; Valhalla as root; the address server's sudo and writable root). **On a Linux host** each key under `.generated/tls/` must be readable by its container's user (`NEXT.md`). [517]
- **No backend request follows a redirect**; the worker's map-server answers are bounded (256 KiB), timed whole and checked; a mail server's refusal is answered as nothing. SeaweedFS lets a non-empty versioned bucket be deleted, so the API's S3 identity never holds bucket-delete. [263, 517]
- **The installer:** `pnpm installer` (`pnpm setup` is pnpm's), `installer:check`, `installer:teardown`. A first run asks the firm's name, email (the local mail catcher or none) and the master passcode twice, unseen; makes every secret once; writes **one owner-only, git-ignored env file per service with only its own logins** (`packages/db/.env`: `adms_owner`; `apps/api/.env`: `adms_api`, `adms_readonly`, the signing secret, the password key and the sealing key (one a purpose, ADR-542; added once to an older installation, recorded as `steps.keys`, never remade if lost; `installer:check` checks the three are there and apart), `SMTP_URL`; `apps/worker/.env`: `adms_worker`) and a secret-free record in `tools/setup/.state/`; creates the four login roles from SCRAM verifiers it makes itself (no superuser, create, replication or RLS-bypass), database `adms` owned by `adms_owner` and `adms_shadow` (owner only); runs `prisma migrate deploy` and the seed as `adms_owner`. A rerun re-checks, resumes, puts back what it can and **stops rather than remake a lost secret**; a stray `DATABASE_URL` is ignored; it amends an earlier URL with the password kept (`EnvFile.amend`). The master passcode's Argon2id hash lives only in the database, handed to the seed in memory; a database that lost it asks for the passcode again. **`installer:check`** re-checks everything (the system actor, `guard_gaps()`, migrations, each service's statement timeout, the policy values in force); a `✗` at the migrations or a setting means one was made elsewhere: `pnpm installer --yes`. *Agent defaults:* the names, the questions. [265, 266, 268, 281, 395, 530]
- **Policy values** (thresholds are policy, never relaxed to pass a test): a name the domain owns; the domain's `Policy` refuses one missing or out of range and never stands a number in; **the release's defaults are the committed `packages/domain/policy.env`**, read by a server app and handed to the domain; **an installation may state its own value** under the same name in a service's env file or environment: it wins, is held to the same range, and one refused stops the start, named, never shown; a new project's settings take it for projects made afterwards. The master passcode's lengths are policy values, read by the installer. [303, 395, 530]
- **This machine's installation holds no person but the seed's actors**: `pnpm local:accounts` and `pnpm installer:admin` are never run for real here; the API's tests rely on it. The master passcode here is a throw-away random value. [396, 401]
- **The map servers** (REQ-022): `routing` (Valhalla) and `addresses` (Nominatim, address lookup only, no search), pinned by tag and digest, reached only through Caddy over HTTPS (`routing.`, `addresses.adms.localhost`), no port published. **One OpenStreetMap extract, named by a URL and a SHA-256 together** (`ADMS_MAP_EXTRACT_URL`, `ADMS_MAP_EXTRACT_SHA256`; built in: Delaware, Geofabrik's copy of 1 January 2026), downloaded once into the git-ignored `infra/local/.cache/maps/`, checked every run; a server rebuilds when the hash changes. **The extract's date is the map's date.** Valhalla answers only `locate`, `route`, `status`; Nominatim's own Postgres is closed outside its container by our wrapper, and its gunicorn runs with no control socket (`--no-control-socket`, task 2.9.2, ADR-552, 554). ### The API: process, boundary and endpoints — ARCHITECTURE §6; `adms-verify`'s API page; BACKLOG's standing rules (the recipe for an endpoint) [380…392, 512, 513, 524]
- **The API** (NestJS on Fastify) is the stack's own service, reached only at `https://api.adms.localhost` through Caddy, HTTPS alone. **It adds no rule: it wraps, signs in, queues and hardens.** After a change to `apps/api` or `apps/worker`, `pnpm local:up` again before the chain (the door and container tests ask the running containers). [376, 380…385, 517]
- **Every endpoint is defined once in `packages/contracts`** with `endpoint()` (every payload a Zod schema there, never in an app) **and served through `@Serves`**; it states who may call it (`access`: `ANYBODY` · `SIGNED_IN` · `PROVEN_PHONE` · `MONITOR_ON_PHONE` …, `roles`, one `permission`), **asked by `Admission` before the schemas read anything**; its rate limit by address and, where somebody is signed in, by them; its request id; and its tests as each kind of caller, in one task. `pnpm openapi` after. **`apps/api/test/every-endpoint.test.ts` lists every endpoint** with its access, roles and permission: one added or opened wider fails until its line is added; each is asked by every kind of caller with a body no schema takes, nothing written, no 5xx, no secret in the log. [387…393, 407…416, 512]
- **What the boundary reads:** only JSON and a part of a file (a form or plain text 415; `bodyParser: false`); a path and query decoded once; `__proto__` refused; an answer is the serializer's JSON; a method not listed answered "not found"; **every number an endpoint takes has a least and a most** (`columnInteger` for a column's whole number; inside it a column's own check speaks); no secret in a path or query; a contract's HTTPS link is the one address taken, never fetched. [424, 513]
- **The log:** one JSON object a line; every refusal at the door logged (`The door refused a request.`: the endpoint, the code, a person's or phone's id where known; never a name, a Monitor ID or a token) and at the boundary (the endpoint and `BAD_REQUEST`, never what was sent). [513]
- **A request the database can't do in time is told `503 BUSY`** (statement timeout per service login), never a 500; three full runs of `pnpm scenarios` in a row pass with no 500 in the API's log (REQ-210). [524]
- **A test of the API that must write** runs in one piece of work on the installation's database, undone afterwards (`apps/api/test/support/database.ts`), and may hand the process its own database, mail and clock; **the API's test files run one at a time**; a signed-in test uses `test/support/served.ts` (`worldOn`, `served.signedIn`, `served.from`, `installationPolicy`). Detail: the API page beside `adms-verify`. [405, 415, 416]
- **The product's code locations:** `apps/api/src/` (service classes by area; `process/` and `main.ts`; `phone/` for the phone's endpoints), `apps/worker/src/` (`reconciliation/`; `process/`), `packages/contracts`, `packages/domain` (every rule), `packages/db`. Only `packages/db` and the two server apps reach Postgres (REQ-205). [508]
- **The process:** `apps/api/src/process/`, started by `apps/api/src/main.ts`; decorators through `experimentalDecorators` in `apps/api` only, **no `emitDecoratorMetadata`** (name what a class needs with `@Inject`), so it runs as built, never by type stripping. Locally a container (the pinned `node` image, built code mounted read-only, uid 1000, read-only root, no capability, no port published; compose profile `api`), started by `pnpm local:up` once `apps/api/.env` exists. **Settings** (`Settings`): the environment first, then the env file (`ADMS_ENV_FILE`, else `apps/api/.env`); a missing or malformed key stops the start, **named, never its value**. **The request id is the server's own** (`requestId`, `X-Request-Id`). **One error filter:** every refusal or failure answers `{ code, requestId }` (`errorAnswerSchema`). **`GET /health` → `{"status":"ok"}`** (liveness, the process alone); **`GET /readiness`** the same while the database answers, else 503 `UNAVAILABLE`, bounded by `STATEMENT_TIMEOUT_MS`. *Agent defaults.* [380…385, 507]
- **The contracts' list:** an endpoint is a name, a method (`GET · POST · PUT · PATCH`), a path and the schemas of its path parameters, query, body and answer; a definition that would take a field nobody named, at any depth, is refused when written. **The API maps a route only with `@Serves(endpoint)`**; the `Boundary` interceptor reads path, query and body by those schemas before any controller runs (a field not named, a wrong value → 400 `BAD_REQUEST`); a route naming no endpoint → 500; a test holds the routes to the list. **OpenAPI 3.1 by `pnpm openapi`** into `apps/api/openapi.json` (a test fails when stale). **A body is one mebibyte at most** (`REQUEST_BODY_LIMIT_BYTES`, `TOO_LARGE` before it is read whole; an installation may raise it, never under a mebibyte, the heaviest sync, ADR-504). **CORS:** `ADMS_CORS_ORIGINS`, exact origins (`https://` or `capacitor://`, lower case, no path, no `*`), matched whole; an origin off the list is told nothing. **Every answer carries the API's headers** (HSTS, `nosniff`, no referrer, a CSP that lets nothing load or frame it, `no-store`, `X-Request-Id`; Caddy removes `Server` and `Via`). **Every write made while a request is answered states its request id**: the API's one database client (`@Inject(apiDatabase)`) asks which request is running, so no service passes it along. *Agent defaults.* [387…392, 504]
- **Each service login is under a statement timeout:** `STATEMENT_TIMEOUT_MS` (30,000 ms), set by `pnpm installer` on `adms_api`, `adms_worker`, `adms_readonly` (`ALTER ROLE … SET statement_timeout`), never on `adms_owner`; `installer:check` reads it as each login; a service's own env file may state another. [394, 395, 396]

### Sign-in, sessions, people and rate limits — ARCHITECTURE §6, §7.0; NIST SP 800-63B-4, ASVS 5.0 [170, 397…417, 530, 531]
- **Sign-in follows the named standards; a departure is said before it is built (the user, ADR-401).** Say what the standard asks and what comparable products do before building a suggested direction; a departure is built only as a risk the user accepted knowing it. **A failed sign-in and a lockout are security events, and lockout state is in the database** (it outlasts a restart and is shared by every API process). ADR-400 is withdrawn: never cite it. [401]
- **Sign-in's records** (each with guards tighter than `guard_table`'s, read by the API alone, audited in the security domain, never deleted): **`UserCredential`** (one a person, apart from `user`: `passwordHash` (an Argon2id PHC string only), `twoStepSecret` (sealed), `lockedUntil`, `failedSignIns`, `passwordChangeRequired`, `twoStepLastStep`; the system actor has none); **`Session`** (one a sign-in; **the SHA-256 of the one refresh token in force**, rotated in place, `revokedAt` final); **`SecurityEvent`** (a sign-in, a wrong try, a lockout, a phone's setup or switch, a use of the master passcode…; `SecurityEventKind`, REQ-202b; added, never edited; copied by the audit capture into `audit_record`; never a typed name, an address or a secret). **The secret columns are named on their audit triggers** (the log says one changed, never what). A failed try is written with the person whose login was tried as its actor. *Agent defaults, seen by the user ("Security is key here").* [397, 398, 399]
- **Passwords** (`packages/domain`: `PasswordRules`, `BreachedPasswords`, `passwordAsKept`): a back-office or outside user's is **15 to 128 characters** (`PASSWORD_MINIMUM_LENGTH`, never under 8; `PASSWORD_MAXIMUM_LENGTH`), any characters, NFC; **never a composition rule, never a forced change**; refused (422, a plain reason) when too short or long, wholly on **the release's breached list** (`packages/domain/breached-passwords.txt`, read at start, no outside service, never on a phone), or only the product's words and the person's own details. **A monitor's password is exempt** (their phone number without the area code, ADR-105). The master passcode is refused by `pnpm installer` when on the list. **The hash:** Argon2id, 19 MiB, 2 passes, 1 lane, 16-byte salt, PHC, `node:crypto` (`PasswordHasher`), **keyed** with the API's own password key (`ADMS_PASSWORD_KEY`, `keyid=djI`); a hash with no key, or keyed `djE` (a key drawn from the signing secret before ADR-542), still checks where that secret is given and is remade at sign-in. **One secret a purpose (ADR-542):** the signing secret signs tokens and codes; the password key keys passwords and the master passcode's verifier; the sealing key (`ADMS_SEALING_KEY`) seals authenticators' secrets and offline seeds (`v2.`; `v1.` read and resealed at the owner's sign-in). Losing the signing secret ends sessions; losing a key sets anew what it keyed. The master passcode's verifier is keyed (the installer's first version at its first use). *Confirmed by the user (ADR-407).* [402…406, 410, 411, 542]
- **Reset by email**, where the firm has mail, for a back-office or outside user, never a monitor: `POST /password-resets` (always `accepted`; a message only when exactly one such person has the address) and `/password-resets/completions`; the code is signed over the person, its end and their current hash (nothing stored), **good once**, `PASSWORD_RESET_MINUTES` (60); it signs nobody in; no mail server → `409 NO_MAIL`. Mail by `nodemailer`, TLS required to every server. **An admin sets anybody's password** (never the system actor's); **a password somebody else set is changed by its owner first** (`PASSWORD_CHANGE_REQUIRED` on every endpoint not marked `beforePasswordChange`). A password set anew ends the person's sessions and opens a lock. [403…406, 410]
- **Sessions:** an admin, a manager/analyst or a read-only viewer signs in with **the email address the firm holds** and their password; never a monitor (their ID opens a phone's calls only), never the system actor. `POST /sessions`, `/sessions/refreshes`, `/sessions/sign-outs`, `GET /sessions/current`, `/sessions/csrf`, `POST /password-changes`. **Tokens are cookies only** (`__Host-adms-access`, `__Host-adms-refresh`; `HttpOnly; Secure; SameSite=Strict`). The access token (HMAC-SHA-256, `ACCESS_TOKEN_MINUTES` 5); **the session, person, role and archive are read from the database on every request**. The refresh token is **good once**: a token not the one in force ends the session. **CSRF:** every non-GET `SIGNED_IN` or `REFRESH_TOKEN` call carries `x-adms-csrf` or is `CSRF_REFUSED`. **The back office and its API are one site.** A session ends at sign-out, `SESSION_INACTIVITY_MINUTES` (30), `SESSION_OVERALL_HOURS` (12), a refresh token used twice, a password set anew, the person archived. [408, 409]
- **Wrong tries** (`SignInTries`): from `SIGN_IN_TRIES_BEFORE_WAIT` (5) each puts a doubling wait (`SIGN_IN_FIRST_WAIT_SECONDS` 30 … `SIGN_IN_LONGEST_WAIT_MINUTES` 60); at `SIGN_IN_TRIES_BEFORE_LOCK` (**50**, the user's, ADR-417; never over 100) **locked until the password is set anew**, never by time; while waiting or locked the right password is refused too and nothing written. **Every failed sign-in is `SIGN_IN_REFUSED` and nothing else**; a try at a name nobody has writes no row. Events `SIGN_IN`, `SIGN_IN_FAILED`, `LOCKOUT`; a locked person is told by email. **Tries at one secret are taken one at a time** in the process (`InTurn`: a sign-in by its address, a phone's by its Monitor ID, a person's own password and two-step removal, the master passcode as one), so a burst is counted try by try, never checked whole against one count (*agent default*, ADR-541). **A person is found by their address with one equality the database's own rule and index answer** (`signingInWith`: `lower(btrim(email))`, `user_sign_in_email_once`), never by reading everybody, and only their credential is read (ADR-547). [409, 417, 541, 547]
- **Two-step** (an authenticator app's code, RFC 6238: HMAC-SHA-1, six digits, 30 s, a 20-byte secret; `OneTimeCodes`): **required for an admin and a manager/analyst; for read-only viewers the firm's choice** (the user, ADR-511) (an admin's switch, `FirmSettings`; a viewer with none is sent to set one up); none for a monitor (`TwoStepRules`). A person with one and no code: `401 TWO_STEP_CODE_NEEDED`; **a wrong or spent code is a wrong try**; a code is good once (`two_step_last_step`); `TWO_STEP_CODE_STEPS_EITHER_SIDE` (1; ASVS 6.5.5 read as the step's length, the user, ADR-414). A required person with none gets a session that opens only setting one up (`TWO_STEP_SETUP_REQUIRED`). Set up by `POST /two-step/setups` and `/confirmations` (**nothing kept until a code proves it**); sealed at rest (AES-256-GCM, bound to its person, `v1.…`; the database refuses anything unsealed). **An admin clears another's** (`POST /people/:userId/two-step-clearings`: their sessions end, an email); **a person removes their own by a code from it**. Dev accounts: `pnpm local:accounts` (never run for real here). [170, 412, 414, 530]
- **Permissions on every request:** every `SIGNED_IN` endpoint names its `roles` and may name one `permission`; `Admission` asks them after the session, CSRF, the password to change and the authenticator to set up: `403 NOT_ALLOWED`. **The role and permissions are read with the session on each request** (`Caller.granted`), so a grant taken away, a role changed or a person archived refuses the very next request. The rule is `packages/domain/src/people.ts` (`Access`, `PeopleRules`): an admin holds every permission; a manager/analyst the ones granted; a monitor, viewer, system actor or anyone archived none. A service behind an endpoint asks again in its own piece of work (ADR-364). [364, 415]
- **People** (`apps/api/src/people/`, `People`): `POST /people` (an admin, manager/analyst or viewer, never a monitor; an email required); `GET /people/:userId` (a monitor's phone number in an admin's answer only); `PUT …/permissions` and `/viewer-projects` (the whole set; one not named archived; **only an admin gives a permission**); `POST …/passwords`, `/session-endings`, `/archivings`. **One email address per person who signs in** (`409 EMAIL_HELD`; exclusion `user_sign_in_email_once`, ignoring case). **The last admin stays** (`409 LAST_ADMIN`; trigger `user_last_admin`). **`pnpm installer:admin`** (the user's, ADR-413, 414), on the firm's server: the first admin where there is none; an admin's password anew and, asked, their authenticator cleared; never a second admin. A refusal may carry the domain's plain words (`message`). [413, 414, 415]
- **Rate limits** (`RateLimits`, the anti-automation beside the login's own count): **`429 LIMITED`** with `Retry-After` and `retryAfterSeconds`, never which limit. By address (`RATE_LIMIT_REQUESTS_PER_ADDRESS` 3,000 in `RATE_LIMIT_WINDOW_SECONDS` 60), by signed-in person (`…_PER_ACCOUNT` 600), by proven phone (`…_PER_PHONE` 600; file parts their own count); refused tries at a secret by address (`SIGN_IN_WRONG_TRIES_PER_ADDRESS` 30 in 60 min) and by address at one login (`…_AT_LOGIN` 4, under the wait); resets by who asks (10) and for whom (3). **A try stopped by a limit never reaches the login** and writes nothing; **a try under way counts against its address's limits as refused** until it is over (`mayTry` answers a try under way, ended in a `finally`; ADR-541). **A request through a proxy the API doesn't trust is logged as a warning at most once an hour**, naming `ADMS_TRUSTED_PROXIES`, never an address (ADR-549). **Counts are in the API's memory, never the database** (start again with the process; `RATE_LIMIT_COUNTS_KEPT` 100,000). A caller's address is the connecting one unless a proxy in `ADMS_TRUSTED_PROXIES` says otherwise (Caddy is `172.30.213.2`); IPv6 by its first 64 bits; **no address is logged or stored**. A shared store for several API processes: 5a. *Agent defaults.* [416, 482, 490]
- **Waits:** a request the database can't do in time is **`503 BUSY`** (`DATABASE_BUSY_RETRY_SECONDS` 5) where no connection came free in `DATABASE_CONNECTION_WAIT_MS` (2000), a piece of work ran past `DATABASE_WORK_LONGEST_MS` (5000, passed to every `$write`, `$read`, `$viewed` of both services) or a statement past `STATEMENT_TIMEOUT_MS`; nothing of it kept. **Every client reads a wait one way** (`toldToWait`: `LIMITED` or `BUSY`) and sends again as it was. A turn-in holds its phone's row first; a top-up reads it under a share lock (a race is `401 PHONE_NOT_PROVEN`, never a 500). **A new piece of work meant to run past 5 s states its own limits** (C166). *Agent defaults.* [524]

### Jobs and the worker — ARCHITECTURE §13; `adms-verify`'s worker page [360, 418…420, 506, 507]
- **The job queue is two guarded tables of our own, written through Prisma; no queue library** (pg-boss keeps its own schema outside the migrations and `guard_gaps()`, deletes finished jobs and writes with no actor). `ReconciliationJob` (project, `trigger`, who (none on a sync's), when; the worker's: `attempts`, `finishedAt` with its run, `lastError`, `setAsideAt`) and `ReconciliationJobTicket` (each ticket as the worker groups one: workflow and bare number, once, its job's own project's). **A job is added only inside the piece of work of the change that asks for it** (`new ReconciliationJobs(tx).queue({ projectId, trigger, requestedById?, tickets })`, `packages/db`), so they commit or are undone together; a job with no ticket is refused (a change that moves no ticket uses `forProjectRecords`). The API adds, the worker reads and updates, nobody deletes, viewers hold nothing. **A job is waiting while neither finished nor set aside, and then never changes again.** A ticket that errors never fails its job (flagged, skipped); a job that fails whole is set aside after `JOB_TRIES_BEFORE_SET_ASIDE` (5) tries, kept and shown, no new flag. *Agent defaults.* [094, 097, 418]
- **What queues work: a change that moves a ticket queues its own job in its own piece of work; nobody asks the worker.** Every such service hands its ask to `WorkQueue` (`apps/api/src/jobs/`), made with `(db, clock, policy)` (`QueueingService`). **A job names the tickets the change touched and their neighbours** (`TicketNeighbours`, four things only: two loads on one certification whose loading times overlap; two crew-time tickets of one crew that overlap or share a project day; two tickets on one scale receipt; a load and a unit rate ticket it carries, and two loads listing one carried ticket), **asked before and after the change**. **Left off every job:** a ticket locked as invoiced (its unlock queues it); among neighbours and a setup change's tickets, a void ticket. **Who queues what:** a correction, renumber, quarantined record resolved, back-office record, void, unvoid: their tickets and neighbours; an acceptance and an unlock: the ticket alone; a rule: its form's tickets; a pay item, a rate, "Pays when", a project's settings, a control range, a map version: every ticket of the project; a site: tickets with a field event at it; a certification made (its number's field events linked to it), measured or revoked: the tickets on its number and those sharing a scale receipt; a sync: what it saved. **Size:** `JOB_TICKETS_AT_MOST` (200): a change is cut into jobs of that size; a run takes waiting jobs oldest first until their tickets come to it, and a job behind whose tickets the run already works rides with it. *Agent defaults.* [090, 360, 420, 506]
- **The worker's process** (`apps/worker/src/main.ts`, a container after the API): looks at the queue every `JOB_QUEUE_POLL_SECONDS` (5) and hands each project with a job waiting to `Reconciliation.waitingJobs`, one project after another. Under the project's lock it counts a try on each waiting job in its own piece of work, works the tickets they name (each once), and finishes each job in the run's closing piece of work. **The run still reads the whole project** (checks read neighbours) and checks the flags on no ticket every run. The run's trigger is the oldest job's. **Settings** (missing or malformed stops the start, named, never shown): `DATABASE_URL`, `ADMS_ROUTING_URL`, `ADMS_ADDRESSES_URL`, `ADMS_MAP_EXTRACT_SHA256`, `ADMS_WORKER_HOST`, `ADMS_WORKER_PORT`, optional CA and address settings. Policy: `RECONCILIATION_RUN_LONGEST_MINUTES` (10), `MAP_SERVER_ANSWER_SECONDS` (30), `DATABASE_POOL_CONNECTIONS` (10, ≥2, each service). **Log:** JSON lines, ids only, never an error's message. **Health** on its own loopback: `{"status":"ok","jobsWaiting","jobsSetAside","oldestJobWaitingSeconds"}`, or 503 `unavailable` with `NOT_YET_LOOKED`, `QUEUE_NOT_READ` or `STALLED`. The installer adds settings to an older `apps/worker/.env` without touching a line (`EnvFile.add`). [395, 419, 507]
- **The worker's other jobs:** revoking a lost or retired phone's key after the firm's time (Phones out of service). [530]
- **A reprocess a person asks for** (the user, ADR-498): `POST /projects/:projectId/reprocesses` (`Reprocesses`; an admin, or a manager/analyst with *correct*): `{ tickets }` (at most `JOB_TICKETS_AT_MOST`) or `{ setAsideJobId }`, a note in the audit record; it changes no record, only queues one `REPROCESS` job naming the person, **the tickets alone, never neighbours**; a locked ticket is left off and counted. Refused: `TOO_MANY_TICKETS`, `NOT_A_TICKET`, `NOT_ON_THIS_PROJECT`, `NOT_SET_ASIDE`. It is how a ticket flagged "could not be processed" is fixed once the cause is gone, and **how a job set aside is put back** (the old job stays set aside as the record). **A job set aside is logged as an error `JOB_SET_ASIDE`** (project, job, trigger, a count of tickets, tries, the kind of failure; never `lastError`, a number or a name); no alert yet (5a). **The back office reads the jobs set aside** (`GET /projects/:projectId/set-aside-jobs`, *view review*: each with what queued it, when, its tries and its tickets, each **waiting** until a job finished after it was set aside has worked it; never why), **and the review queue marks and counts those tickets** (`waitingOnSetAsideJob`, `waitingOnSetAsideJobs`) (ADR-545). *Agent defaults.* [498, 499]
- **A locked ticket and a setup change (the user):** a ticket locked as invoiced is on no job, and a setup change's run writes nothing on it. **A saved change answers how many tickets it queued and how many locked ones it reached and left** (`Outcome.queued`). Phase 4: the screen, and a mark on a locked ticket whose setup changed since it was priced. [057, 090, 420, 422]

### Sync, intake, quarantine and held records — ARCHITECTURE §9; `adms-exceptions`; `spec/DATA-MODEL.md` §4.5 [338, 466…475, 504, 505, 526, 531]
- **The sync contract** (`packages/contracts/src/sync-records.ts`, `sync.ts`): seven kinds of record (a field event with its item lines and carried tickets, a scale receipt, an incident, a drop-off log, a survey, an ROE, a certification), each a strict schema under `syncedRecordSchema`. **A schema says what a record can be at all, never whether the work was right** (ADR-052): an unknown field refused, every value bounded by what the database keeps, a detail belongs to its kind; a gap, an end before its start, an impossible GPS fix and a number that isn't digits are taken as sent. **No record names a conclusion, money, a certified capacity or its phone** (`deviceId` and `source` are the server's, from the proof); a phone's field event may carry `typedCapacityCy` (a truck keyed in by hand). A time travels as a UTC instant with its offset. **A certification never sends a capacity:** its boxes as measured (whole inches), the server works it out; never a QC status, signatures, a revocation or who a typed sub is; its photographs are photograph records naming it. [052, 466, 469]
- **One sync** (`syncSentSchema`, read in order): the phone's clock and offset, its unplanned assignments and logged passcode uses, its records, the last number used per series, what it holds (`holds: { masterPasscodeVersion, listsProjectId }`); then `photos`. **Each record is read on its own** (`recordRead`), so one that isn't a record never refuses the sync or the others. **A phone's daily budget of what it makes the server hold** (ADR-546): each held record keeps its size (`sent_bytes`); past `PHONE_HELD_BYTES_PER_DAY` (16 MiB) or `PHONE_HELD_RECORDS_PER_DAY` (1,000) in 24 hours, still received and held, but once a day a security event `PHONE_HELD_BUDGET_PASSED`, every admin mailed, and the phones list's `heldBudgetPassedAt`. **Bounded:** 200 records, 20 unplanned assignments, 100 uses, 20 series, 200 photographs' records; **a sync weighs a mebibyte at most** (`syncBytesAtMost`; a client fills up to counts or weight, `fitByWeight`); **a record 256 KiB at most** (a heavier one is `NOT_A_RECORD`, held). **Answered** (`syncAnsweredSchema`, one answer per thing sent, in order): `SAVED` (with notes), `ALREADY_SAVED`, `QUARANTINED` (reason, words, the record holding the number) or **`NOT_SAVED`, held on the server for a person** (the user, ADR-468): `NOT_A_RECORD`, `NAMES_NO_RECORD`, `ASSIGNMENT_NOT_SAVED`, `CERTIFICATION_REFUSED`, `REPORT_NOT_SAVED`; a record that isn't one is told which field and how, never a value sent. A record under another monitor's assignment is saved as sent, and flagged (ADR-543, 551). **Who a field event names is asked once as it arrives** and kept on its ledger row (`synced_record.monitor_id`, `monitor_signed_in`): whether that person held the phone over its field time (a session of theirs there begun before it ended and not ended before it started, a session past its hours still counting; the phone set up for them under the passcode; or the board's assignment of theirs on that very phone with nobody else signed in on it then); the worker flags `MONITOR_NOT_SIGNED_IN` from it (approved by the user, ADR-551). Per series: the blocks held and `toppedUp`. [467, 468, 469, 504, 526]
- **`POST /phones/current/syncs`** (`Sync`, `apps/api/src/sync/sync.ts`; `PHONE_IN_USE`, `outOfServiceToo`): a `Sync` row first (the phone's clock less the server's, whole seconds), then each part in the payload's order, each its own piece of work and answer. **A record:** the ledger asked first (`ALREADY_SAVED`); the server adds `source: 'DEVICE'` and the phone; `Intake.receive` or `Certifications.received` stores it **with its ledger row and its job in one piece of work**, as the monitor from the phone. **What a sync queues** (trigger `SYNC`, no person): a saved field event's ticket and neighbours; an ROE's waiting tickets; a survey a job naming none; a certification as `certify` does; a scale receipt, incident, drop-off log or quarantined record nothing. **Numbers:** `NumberAllocator.topUp` as the device key's actor; a top-up that loses its race three times answers `toppedUp: false` with the blocks held, its records saved (ADR-505); a phone out of service is topped up never. **The answer brings, to a phone in service only:** `masterPasscode: { version, check }` (a check only where the phone holds another) and `setupVersion` (made where it moved; `Sync.setupVersionSent` written once); **never the lists or the login list** (their own reads, ARCHITECTURE §9 (6); the user, ADR-474). The log carries the phone, the sync's id, the difference and counts by answer, never a record or message. [472, 473, 474, 505, 531]
- **The device clock:** the worker reads each phone-made field event's sync (through `synced_record`) and **flags `DEVICE_CLOCK_OFF`** where the phone was more than `DEVICE_CLOCK_OFF_LIMIT_MINUTES` (5, the user, ADR-474; 1–1,440) whole minutes off, ahead or behind (6 m 00 s is, 5 m 59 s is not); a back-office record has none. [473, 474]
- **The tables:** **`Sync`** (the phone, the server's time, the phone's clock and offset, the difference held by the database to the two instants, the setup version sent; written once); **`SyncedRecord`** (the idempotency ledger: one row per record **stored**, `SAVED` or `QUARANTINED`, its kind, sync and phone; written once); **`HeldRecord`** (what the server could not save: its own id, the phone and sync (null only for a report at its own endpoint), the record's id, project and monitor as sent, **what was sent as any JSON with its SHA-256** (canonical JSON, keys sorted, so the same thing in any field order is the same held record), the reason, what the phone was told ("… Held on the server for review."), and a person's resolution). Each written only for the phone it names (`sync_from_its_phone_guard`). The worker reads `sync` and `synced_record`, nothing of `held_record`; a viewer sees a held record as a quarantined one. [468, 471, 472]
- **Intake** (`Intake`, `apps/api/src/sync/`): each record written as the monitor who made it, from their phone, with the server's received time. **A retry is known by the phone-made id.** **A duplicate** (a second field event of one kind on one project, workflow, bare number and split suffix; an ROE number the project has) goes whole into **`QuarantinedRecord`** (its id, project, phone, monitor, `payload` as sent, the reason `DUPLICATE_FIELD_EVENT` · `DUPLICATE_ROE_NUMBER`, what holds the number, received time, later a person's resolution). **The first received holds the number**, a voided ticket's field event included. What a phone sent is never changed or deleted; the worker never reads it. **Intake fills in** the certification a cert number finds, the ROE a number finds (pointing earlier records at an ROE when it arrives) and a debris type's form; **it refuses nothing else**: a record with a gap is saved as sent, `PENDING`. **An impossible GPS fix isn't written:** the field event is saved without it and the fix kept in `FieldEvent.unreadableGps` (`GpsFix`). The phone's words are the domain's `Quarantine` ("Ticket 101020: this ticket already has a disposal. Not saved: kept in quarantine for review."). Viewers see that a record waits, its contents only where the firm lets them see private citizens. *Agent defaults, for the user: an ROE's quarantine, first received holds, the wording, a viewer's sight, where an unreadable fix is kept.* [338]
- **What a sync holds for a person, read and resolved:** `GET /held-records`, `/set-aside-files` (and `…/:id/file`), `/quarantined-records` (an admin, or a manager/analyst granted *view review*, ADR-539; paged, oldest first, by project and/or phone, waiting or not; `HeldReads`, `HeldReview`, `apps/api/src/review/`). **A held record is resolved once, by a person, with a reason:** *saved as corrected* (`POST /held-records/:id/savings`, *correct*: the record as it should be, in the sync's shape, **under the id its phone made and the kind it was sent as**, written as the phone's record by the reviewer; its photographs move to it; its tickets queued as a correction's) or *closed, never to be saved* (`…/closings`, *void*). **A file set aside is closed only** (`POST /set-aside-files/:id/closings`, *void*). The database holds each resolution to once, by the person named (`resolved_once_guard`), and a held record's photographs to it (`photo_held_record_guard`). Held writes go through `HeldThings` (`apps/api/src/sync/held.ts`). A record held and then saved as corrected is `ALREADY_SAVED` when sent again. *Agent defaults.* [526]
- **The sync client's contract** (`syncClientSuite`, `packages/contracts/src/sync-client-suite.ts`; no test runner, no server): every part sent, each record once under its phone-made id, a scale receipt ahead of the disposal pointing at it, no record ahead of its unplanned assignment, within the limits and the weight; **only `SAVED` and `ALREADY_SAVED` take anything off the phone**; `QUARANTINED` or `NOT_SAVED` kept and shown with the server's words; **no answer marks nothing**; a wait (`LIMITED`, `BUSY`) sent again as it was; files sent only once a record is saved; **a photograph answered `OWNER_NOT_SAVED` sent again once its record is saved; opened again mid-file, a client asks where the file stands before it sends more** (`photoFileStandsAt`, ADR-579); **wipe only on `wipe: true`**. `syncAnswerRead(sent, answered)` is the one rule for reading an answer. The harness's phone is the first client; **the field app's `PhoneOutbox` passes it too, over the phone's own store** (ADR-578). [470, 483, 487…490, 524, 578, 579]

### Product and scope — `adms-domain`; `spec/VISION.md` [197, 224, 228, 230, 561, 573]
- **The firm's setup decides how things play out.** Hardcode as little as possible; ship defaults tailored to debris work that the firm can change. Before proposing a new ticket type, unit, criterion or behaviour, or asking how a contract line works, check whether projects, names, codes, rules and lists already express it; which price a contract means is the firm's call. Work the prime bills outside Open ADMS isn't set up. [197]
- **Two sides.** The monitor enters **only the main ticket**, fast; fees, pricing, zones, mileage and checks are the system's work. The back office sees **everything**, laid out to review, correct and QC many tickets quickly. Before asking a monitor for something, check whether the system or the back office can supply it. **The rules are the firm's own tool** (create/delete transactions, void, any criteria, date ranges): enable options, never hardcode a firm's rules. The user answers wearing different hats (a firm setting up, a monitor, the back office): note which; design each side for its own user. [224]
- **Scope settled from the legacy screens:** out: work orders, purchase orders, Service Categories; Time and Material = crew time; Stump Collection = the load of stumps; **no separate crew list, the crew certification is the crew**; **one review queue** (photos reviewed inside a ticket); reports = fixed exports plus saved filters (a query builder later); **a firm library plus "copy from a past project"**; **invoice batches**: a named set of tickets locked as invoiced. [228]
- **Question shot-clock:** product discovery is closed. Ask only when the answer changes money, evidence or the monitor's work, blocks the task, and nothing covers it (at most three, each standing alone with a recommendation); otherwise record an **agent default** ADR, list it in §4, and carry on. Spec approvals don't block building. [230]
- **One organisation per installation**, usually a monitoring firm; **self-installed open source**, no multi-tenancy. [050, 063]
- **No USACE mode.** Every project runs the same rules, plus an optional "USACE approved" flag on the load call. [077]
- **The deliverable is the client package, assembled by hand** by the back office from the system's data. **There is no invoice record:** "invoicing" means locking tickets as invoiced; a ticket in review can't be locked. No placard printing. [057, 061, 067, 088]
- **A separate project per funder or kind of work** (ROW, PARKS, WATERWAY, federal-aid roads…): commingled data is rejected by FEMA. No funder field. [148]
- **Every load has a monitor at both ends**; no unmonitored disposal sites. Everything comes into the system; paper logs are a monitor's own backup. The back office may **create any record** (e.g. a device failed), marked with the person and a reason, flagged, pairing normally. [156]
- **Citizen drop-off sites are in scope; a drop-off is a reference log, like an incident, not a ticket:** site, monitor, phone time and GPS, optionally the resident's name and origin address, up to 8 photos, notes, the firm's own form fields; no quantity, number, receipt, pay item or cost; searchable by site, dates, name, address. **A form a phone is set up for at a site**, switched on per project and phone like incidents, **QC'd on its own**. The pile bills only when **hauled out as an ordinary haul-out**. [184, 188, 215]
- **Lists: built-in values plus the firm's own.** The system acts only on a built-in value's **fixed key**, never its name; built-in values can be renamed, not archived; the firm's are labels, added, renamed and archived (audited, never deleted); new behaviour means a new built-in value in a release with an ADR. How: `spec/LISTS.md`. [194, 302]
- **Time clock:** an optional per-project add-on (off until the firm switches it on) for workers' own hours (ICS-214 data), on the **assignment**: anyone with an assignment clocks in, takes a break and clocks out **by hand**; simple nudges only ("You're not clocked in. Clock in now?" on starting a field event; "Clock out?" on signing out); activity lines pre-filled from the day's field events, edited and approved by the worker; **a manager approves the day** (locked, unlock audited); **exported** for payroll and billing. No hourly rates or pay in Open ADMS; viewers don't see hours (*agent defaults*). **Never related to crew-day billing.** Its tables and screens: Phases 3–4. [063, 100, 241, 304]
- **Local first:** test in a browser, then iPhone, then Android. Firms host in **their own cloud**; **Railway + Netlify is the shipped demo deploy**. Sync needs a data connection. [099]
- **The user's Build 1 answers bind** (`spec/FROM-BUILD-1.md`, verbatim) unless a newer ADR differs; Build 1 code is never a source. [102]
- **Every screen translatable** from day one, English only at first; **US units only**. [172] The field app's words are its translation file, `apps/field/src/words/en.json` (typed by `words.ts`; the page's title and language written in from it at build); no screen writes a word of its own (AC-11-04). [565]
- **The field app's design (the user's, ADR-561):** built for a monitor outdoors, gloved, one-handed and interrupted: speed and no mistakes first. A high-contrast light theme by default and a dark one; large type and main buttons (about 56 px); a state is an icon and a word, never colour alone; **one look on iPhone and Android**, each keeping its own safe areas, back gesture and keyboard. Home is the day's assignment; a status strip on every screen (what waits on the phone, the clock, who's signed in); the main action at the bottom; capture one question a screen, review, the number, print, next (the number now taken at New after the badge, and a ticket left and resumed from home's open list, ADR-571). **Our own small component set on React Aria** (its version by its task's ADR), the look as tokens the back office can share; not Ionic's components. **Before any capture screen, the key screens are a clickable prototype for the user** (task 3.1.4), with the open designs put to them there: a confirmation after each value, a monitor scorecard, the bottom menu, the number typed again (ADR-209, WCAG 3.3.7). Answered (ADR-573): see below. [561] **Built (ADR-567, 568):** React Aria Components (exact version by ADR); the tokens in `apps/field/src/look/tokens.css` (light on the bare root, dark by the phone's setting and by `data-theme`, every colour pair AA in both, type in `rem`); our components in `src/look/` (button and row, list picker, number keypad, scan field, photo strip, progress header, status strip, banners); **every screen is built from them**. React Aria's inline style is answered by the app's own stylesheet, never the policy loosened; no screen uses a spin button or a modal (they write HTML or styles the policy refuses). The prototype (`apps/field/prototype/`) never ships. **The four open designs, answered by the user (Q-215…Q-218, every recommendation approved):** no confirmation after each value (the review screen shows everything once); the monitor's own count of today's tickets on home, nothing ranked; **the bottom menu Work, Time (only where the project has the time clock on), Sync, Settings**; the number typed again only where a person copied it (WCAG 3.3.7 met as essential). [561, 567, 568, 569, 571, 573]
- **Enterprise readiness:** operations monitoring, availability, independent security testing (a threat model, a penetration test, how a vulnerability is reported) and accessibility are each in BACKLOG's register (C38…C41) with what exists, what's missing and when to raise it; **accessibility: every screen meets WCAG 2.2 AA, and a conformance report (VPAT format) ships for each app at its phase's end** (the user, 559; REQ-324, C41). **Operations monitoring's Phase 2 part is built:** the API's liveness and readiness, the worker's and the queue's health, error reporting as the structured logs; alerts and the rest are the demo deploy's (5a). Server backups: ARCHITECTURE §4; upgrades: Q-167; single sign-on is not planned. [279, 507, 559]

### People, permissions and read-only viewers — `adms-domain` §1.4, `adms-data-model`; ARCHITECTURE §6 [050, 105, 169, 240, 315, 361, 539]
- **Roles:** **admin**, **manager/analyst** (granted permissions), **monitor** (through a device), and **read-only viewers** (client users, contractor users, auditors) for their own projects. **Creating users:** monitors on a phone, online, by the master user; back-office and outside users by an admin. [050, 105]
- **Enrol once, dispatch daily.** A phone is enrolled once (online, the master passcode: its device key; no project, no monitor). The back office writes each day's **assignments** on a **dispatch board**: person, date, project, their work (ticket types, unit rate pay items, certifying), **one site** where the work is at one, optionally a phone; copy yesterday's. The monitor signs in on any enrolled phone; **online, the phone gets their assignment**, the project's lists and numbers: no passcode, no picking. **One assignment, so one project, on a phone at a time** (a tower monitor working two projects carries two phones). **Unassigned**, the master passcode sets the phone up (offline only on the project whose lists it holds), recorded as an **unplanned assignment** (marked, not flagged). The board shows planned against actual as views, never ticket flags; **an assignment never expires or stops work.** Not taken: passkeys, attestation, personal phones, per-supervisor keys. [145, 240]
- **Workers** have a **system Monitor ID** (the database issues it: `M` and six or more digits, one series from `M000001`; unique; never the system actor's) and optionally an **employer** (a contractor record, `User.employerId`, with the employer's own ID for them, `employerNumber`), kept apart from a viewer's contractor; subcontracted monitoring firms and temp agencies are contractors (monitoring kind). Each field event records its own monitor. [102, 281, 527]
- **What read-only viewers see:** clients and auditors the whole project except personal phone and licence numbers; a contractor only its own tickets and transactions (a prime with its subs'), never another prime's; monitors' phone numbers only admins. Enforced by row-level security. An admin issues a viewer its kind, its projects and, for a contractor user, its contractor. [169, 315]
- **Permissions:** `UserPermission` (a person and one of the thirteen permissions, once; **taken away by archiving, given back by clearing it**, never a second row; never the system actor's; tied to the role manager/analyst by the API, not the database). [315]
- **What the back office sees is granted too (the user, ADR-539):** three view permissions, `VIEW_REVIEW` (the review queue, tickets with their lines' rate and amount, field events, flags, receipts, certifications, ROEs, surveys, incidents, drop-off logs, a ticket's run decisions, held, quarantined and set-aside records, invoice batches, a photograph's file), `VIEW_SETUP` (setup but its rates, the setup check, the lookups, maps and shapes) and `VIEW_DISPATCH` (people, phones and their sessions, the board). Every one of the back office reads the projects and the lists' values. **An act needs its area's view beside its own grant** (`Access.holds`: the review acts with *view review*, Setup with *view setup*, Dispatch with *view dispatch*; approving hours none yet); a pay item's rates take Setup (so *view setup* too). An admin holds every one. Asked at the door (each read's endpoint names its view) and again inside the read (`backOfficeSees`, `backOfficeReader`). A ticket's money travels with *view review* (the user: kept as it was). [539]
- **Read-only viewers:** `User.viewerKind` (`CLIENT` · `CONTRACTOR` · `AUDITOR`: every viewer states it and nobody else; **a contractor user names its contractor** and nobody else does); `ViewerProject` (table `user_viewer_project`, a project once per viewer, taken away by archiving). **The API states only `adms.viewer_id`;** the database reads the person (a viewer, not archived), their projects, kind and contractor with the owner's rights (`viewer_sees_project`, `viewer_sees_every_ticket`, `viewer_is_contractor`); anyone else, or nobody, sees nothing. **A table gets its viewer sight in one line:** `SELECT guard_viewer('<table>', '<PROJECT|PART_OF|NAMED_BY|FIRM>'[, relation, column][, hidden]);`. [315]
- **What each viewer sees:** **a client user and an auditor** see their projects' whole setup, the project's settings (`viewer_project_setup`, the one view with the owner's rights), the client, declaration event and contractors their projects name, the firm's lists, and their projects' rules. **A contractor user** sees the project's name, time zone and dates, its own place on the project and (a prime) its subs', and its own tickets (next bullet); no setup. **No viewer reads** a contact name, email or phone, a client's notes, a map's file key, or any person, permission, phone, assignment, number block or the master passcode. *Agent defaults.* [315, 361]
- **`Assignment`** (the day's dispatch): person, work date, project, the kinds of field event they may record, certifying, an optional site and phone, its forms (`formDocumentTypes`) and unit rate pay items (`AssignmentPayItem`, held to its own project); `PLANNED` (with its author) or `UNPLANNED` (no author, always its phone, its id from the phone); withdrawn by archiving, put back with its note; no uniqueness on person or phone and day. **Every field event carries `assignmentId` and `setupVersion`**, corrected by permission like any captured field. *Agent defaults.* [281, 286, 301, 527]
- **A contractor user's own tickets are told in one place: the certification its field events found** (fail closed: a field event whose badge found none is no contractor's). It sees, in its projects, the certifications naming its contractor (as prime, so a prime sees its subs', or as either tier of sub), with boxes and helpers, never the driver's phone or licence number; the field events that found one, their completed records, scale receipts and photographs' records; its own place and its subs'; those contractors by name. No flag, monitor's name, ROE, form, quarantined record or list. **A sub's contractor user reads no rate and no amount (the user):** `viewer_transaction_money` shows them only to a client user, an auditor and the line's own prime's contractor user. Every viewer given the project reads three names of setup (`viewer_pay_item_name`, `viewer_disposal_site_name`, `viewer_debris_type_name`). **`guard_viewer` takes `own`** (what makes a row a contractor user's own); **every rerun of a table's line repeats its `own`** (`packages/db/test/support/viewers.ts` holds each). *Agent defaults but the money, the user's.* [361]
- **Whether a viewer sees private citizens by name is the firm's choice per viewer (the user, ADR-328 (4)):** `User.seesPrivateCitizens`, on every viewer and nobody else, no database default, a new viewer starts at yes (`ViewerSettings.starting()`), audited. The columns naming a citizen (an ROE's `owner_name`, a drop-off log's `resident_name` and `origin_address`; *agent default*) are in no `viewer_<table>` view; `viewer_roe_citizen` and `viewer_drop_off_log_citizen` show them only to a client user or auditor whose record says yes. One line says it: `guard_viewer('roe', 'PROJECT', citizen => ARRAY['owner_name'])`. A migration that writes a row states its actor inside one `DO` block. [328, 336]
- **Dispatch takes `DISPATCH`** (an admin, or a manager/analyst who holds it now; `DispatchRights`; `apps/api/src/dispatch/`: `Phones`, `Assignments`, `MasterPasscode`). **The board:** `POST /projects/:projectId/assignments` (a person, a day, their work: `fieldEventKinds`, `certifying`, `formDocumentTypes`, `siteId`, `deviceId`, `payItemIds` (unit rate only)); **for a monitor, an admin or a manager/analyst in service; never a viewer, the system actor or somebody archived; never on a phone out of service**; `PATCH /assignments/:assignmentId` (work, site, phone, pay items; **person, day and project never change**); `…/withdrawals` (with a note) and `…/reinstatements`; `GET /projects/:projectId/assignments?workDate=` (paged). Changed or withdrawn any time while it stands, audited, queueing nothing. **One made on a phone is the phone's** (`MADE_ON_A_PHONE`). Nothing stops a second assignment (AC-02-29); **the board warns** (`GET /assignments`, searched by person, phone or project over 62 days at most, across projects; the domain's `BoardWarnings`: a second assignment for the person or the phone that day, a day outside the active window, a closed project, unit rate pay items with no unit rate work, a site not yet active or closed), never stopping a write (ADR-535). **Phones:** `GET /phones` (name, status, times, the mark, its reason by name, which revoked its key, the passcode check's version and whether current; never its key); a phone's sessions, newest first (whose, when, ended, which way a passcode session was opened, from an offline sign-in or not; never a token); removal, rename, return (Phones). [535] **`POST /master-passcode/versions`** (an admin's alone, giving their own password again): 8–128 characters, never a breached one or the one in force; a new version keyed and with its offline seed sealed (ADR-542); every admin mailed; a phone's check moves at its next sync. *Agent defaults.* [428, 429, 527, 530]
- **People's changes:** `GET /people` (paged; one `role`; archived or not; searched by what a name holds and ordered by name, ADR-535; a monitor's phone number in an admin's answer only; never the system actor); `PATCH /people/:userId` (an admin; name, phone, email (changed, never cleared but on a monitor, `EMAIL_SIGNS_IN`), employer and its ID, and on a viewer its kind, contractor and `seesPrivateCitizens`); `PUT /people/:userId/role` (**between admin and manager/analyst only**, `NOT_BACK_OFFICE`; the only admin stays one); `POST /people/:userId/unarchivings`. **Where a sign-in address changes, the old one is told** (ASVS 6.3.7). Archiving is only for a person who left (and a list's value). *Agent defaults.* [427, 527, 529]
- **Every read for a read-only viewer goes through `ViewerDatabase.$viewed(viewerId, work)`** (`packages/db/src/viewer.ts`): one read-only transaction as `adms_readonly` stating `adms.viewer_id` first; **`apps/api` never filters a viewer's rows itself**: what comes back is what the database shows that viewer now. **A viewer's reads are their own endpoints under `/viewer/…`**, each a GET open to `viewerOnly` (`apps/api/src/viewer/`, `ViewerReads`): projects; one workflow's tickets; one ticket (its field events, the completed record with its rows, its lines) asked by project, workflow and bare number; ROEs. **A ticket the viewer isn't shown is 404, exactly as one nobody has.** What the database doesn't show is `null`. The owner's views are declared in `packages/db/prisma/schema/viewer.prisma` (Prisma `views`, never migrated by Prisma). A viewer sends nothing but GETs and their own password and authenticator. **Since task 2.8.8 a viewer reads the same records as the back office** (ADR-535 (6)): beside a ticket its flags and whether each is accepted, photographs' records, scale receipts, item lines, carried tickets, QC status and lock in force with its batch's name; an ROE's parcel, address, fix and scope; a project's certifications (boxes, helpers counted, names where shown), surveys, incidents and drop-off logs (a resident only from `viewer_drop_off_log_citizen`, now declared); and **for a client user and an auditor** the setup without a rate, the setup check and the lookup (the same domain rules read through `$viewed`; whether the viewer is shown them is `viewer_project_setup`'s, now declared; a contractor user 404). Exports and a page's filters: Phase 4. *Agent defaults.* [434, 435, 535]

### Phones: enrolment, sign-in and lists — `adms-field-app`; ARCHITECTURE §7–§8 [095, 096, 105, 106, 120, 240, 436…455]
- **"Set up", never "provisioned".** **One master passcode per firm**, set at install, changed when the firm chooses, no reminders; neither NIST nor ASVS provides for a secret several people share: **the one master passcode is ADR-106's accepted risk** (THREAT-MODEL §5 (4)). Setup under the passcode (the unassigned fallback): one project, its ticket types and **one monitor** from a list; that monitor signs in offline against a stored check; the master passcode can also sign in as them; **changing the monitor on a phone needs the passcode first**; a temporary session for a roster monitor is a marked shortcut. Monitor credentials work only on set-up phones (ARCHITECTURE §7.2's five safeguards). [095, 105, 106, 120, 139]
- **Device data is encrypted, never backed up, bound to that phone**; a phone can be synced and turned in **without the monitor**, so its key never comes from a password. A device records its id on every record it creates; it sends whatever GPS fix it has (the back office checks and adjusts drift; no accuracy check). [083, 096]
- **`Device`:** a name (the board's, `P1-COL-1`), a unique public key, a status (`ACTIVE` · `LOST` · `RETIRED`, out of service exactly from its removal time), the version of the passcode's check it holds, its number blocks, `outOfServiceMarkedAt`, `keyRevokedAt`/`keyRevokedBy`; **no details column**. *Agent defaults.* [281, 530]
- **The device key and its proof:** ECDSA P-256; a proof is its SHA-256 signature over `open-adms/phone-proof/v1`, a line break and the server's challenge (`PhoneProofRules`, `packages/domain/src/phone-proof.ts`); the server keeps the public half only (`DeviceKeys`). **A challenge is kept nowhere** (signed by a key drawn from the signing secret, `PHONE_CHALLENGE_SECONDS` 120) **and is good once** (`Device.lastAnsweredChallengeMadeAt`, compared and written in one statement; only that phone's proof writes it). `POST /phones/:deviceId/challenges`, `/proofs` (nobody signed in) → **a phone token** (`PhoneTokens`, kept nowhere, `PHONE_TOKEN_MINUTES` 15, `Authorization: Bearer`; access `PROVEN_PHONE`, the phone read from the database on every request). A revoked key proves nothing and its token stops at once. A bad proof is `401 PHONE_NOT_PROVEN`, writes nothing. `GET /phones/current` answers what the server has of it. **Two actors that are no person:** the master passcode's (`…0002`, `underMasterPasscode(deviceId)`) and the device key's (`…0003`, `byDeviceKey(deviceId)`), each stated only by the API with source `DEVICE` naming the phone; **no column that names a user may name either** but the audit record's actor (a later table naming a user adds that check). [436, 437, 438, 439, 440]
- **Enrolling:** `POST /phones/enrolments` (a name, the master passcode, the public key); written as the master passcode's actor. **`MasterPasscodeCheck`** (`apps/api/src/phone/`) is the one check for every act under it; **wrong tries** on `master_passcode_tries` by sign-in's numbers (a wait from the 5th, a lock at the 50th until an admin changes the passcode; an address stopped at its fourth). **Its wait holds only an address refused at it within the longest wait**; the right passcode from anywhere else is taken; the lock holds everybody; **every admin is mailed at the first wait and at the lock** (ADR-541, the audit's F1; *agent default*; a second thing to enrol is the user's to decide). **Its first right use keys the installer's verifier and seals its offline seed**, once (ADR-542). Events `MASTER_PASSCODE_USE`, `…_FAILED`, `…_LOCKOUT`. Refusals `401 ENROLMENT_REFUSED`, `422 DEVICE_KEY_REFUSED`, `409 ALREADY_HELD`. [438, 439]
- **A monitor created on a phone:** `POST /phones/current/monitors` (`PROVEN_PHONE`, in service, the passcode beside the name, password, optional phone number): the database issues the Monitor ID. **The standards' view of a monitor's sign-in is ADR-441:** the seven-digit password, a shared phone and the shared passcode are the user's accepted risks (ADR-105, 139, 240, 106); the device key makes it two factors in shape. [441, 442]
- **A monitor signs in on a phone:** `POST /phones/current/sign-ins` (`PROVEN_PHONE`; Monitor ID and password only, no passcode, no project): a **session row naming the phone**, its token kept as a SHA-256, sent as **`x-adms-monitor-session`** beside the phone's bearer token; access **`MONITOR_ON_PHONE`** (`monitorOf(request)`), proof then session read every request. **It lasts the firm's hours** (`FirmSettings.monitorSessionHours`, 1…24, 24 as shipped, an admin's, `PATCH /firm-settings/monitor-sessions`), quiet never ends it; **one monitor at a time on a phone**. Wrong tries follow everybody's rule on the monitor's own credential (events name the phone; no lock mail). The database holds a monitor's session to a phone in service with its key standing (AC-02-39). [443, 531]
- **The assignment taken at sign-in** (`AssignmentRules.takenAtSignIn`, `PhoneAssignments`): of the monitor's assignments that stand, those whose day is today **in their own project's time zone**; the one naming this phone; where several name it, **the one made on it last by the phone's clock**; with none naming it, the only one there is; **where several are left the phone takes none** (`noAssignment`: `NONE_THAT_DAY`, `SEVERAL_THAT_DAY`; nobody picks a project on a phone); signed in all the same. Told id, day, project (with time zone), kinds, certifying, forms, site: **never a rate, a code or a pay item.** Nothing records that a phone took one. [444, 458, 459]
- **The lists a phone takes** (`GET /phones/current/lists`, `MONITOR_ON_PHONE`; `PhoneLists`): the assignment taken now (the sign-in's rule again) and its lists, or none (the phone keeps what it holds); nothing written. They hold: its number blocks; the load and haul-out forms' debris types by name (not *Hidden on phones*); field tags; reasons for a typed number; **the unit rate pay items the assignment names** (code, band, payable type, kind of work, the seven capture settings) with item names; incident and survey lists where its forms make them (each survey work type with its built-in key since ADR-584); **the forms its assignment makes, each with "GPS required" (the ROE form's) and the newest version of the firm's own fields** (ADR-584, C69; in the setup version, a new version of the fields a new one); **every certification of the project** (number, kind, whole-CY capacity, prime and subs by name; never the driver, tag or measurements; revoked and replaced too); **the live sites** (name, type, *Takes loads*, *Haul-outs leave here*, and since ADR-553 their place, below); **the ROEs** (number, address, parcel, `preWorkSurveyDone`; never owner, signature or scope) only where its work needs one; the live control ranges; **for an assignment at a site, that site's quantity lookup**. **Never a rate, a rule, a transaction, a description or a load's pay item**; the one code is a unit rate pay item's, which the phone prints. **A proven phone with nobody signed in reads no lists.** *Agent defaults.* **Built in task 2.9.1 (the user's choices, ADR-552 (3); the shapes agent defaults, ADR-553):** to an assignment that certifies or takes disposals (`DIS`, `HOD`), **the truck lists**: `vehicleTypes` (each with `kind`, CONTAINER or CREW), `vehicleFeatures`, `crewTypes` in service in the firm's order, and `primes`, each with its `subs` (id, name, `tier` 1 or 2; a sub still typed by name, ADR-108; the prime's offered); never a contact; to a certifying one, **`helpers`**: the others with an assignment on the project that day, not withdrawn, id and name alone; to every phone (and to a phone being set up), **each site's `latitude`, `longitude` and `area`** (`SHAPE`, its newest own shape with its box, or else `CIRCLE` with the project's `siteCircleMeters`) for an advisory, never a refusal. **Every choice a phone offers comes from a list it was sent; the harness's phone stops a story that sends an id it wasn't sent or didn't make** (a record handed to it is exempt), and a record goes as it was made whatever lists the phone holds later (the sync suite's check 19). [449, 450, 451, 530, 552, 553]
- **The setup version** numbers the project's setup as its phones are shown it (how it numbers its tickets, its series and whether it allows split loads since ADR-581; lists, sites with their place, pay items, quantity lookups, and since task 2.9.1 the truck lists, so a vehicle type, feature or crew type changed, a sub placed under a prime, a site's GPS or shape or the project's circle changed each make a new version, ADR-552, 553; **never certifications, ROEs, helpers or blocks**): made when a phone is first sent lists that differ from the newest, as the device key's actor; `setup_manifest` 1, 2, 3… with no gap, never a duplicate; every field event records it (no foreign key: evidence is never refused). `GET /sites/:siteId/quantity-lookup?setupVersion=N` answers the site's rows as kept then. `SetupVersions`, `apps/api/src/setup/setup-versions.ts`. *Agent defaults.* [453, 553]
- **The login list and the passcode's check** (`POST /phones/current/login-list`, `MONITOR_ON_PHONE`): **the phone says what it holds and is made only what it lacks** (an entry is a slow hash). On it: monitors in service with an assignment that stands on the taken assignment's project, today or later, who have an **offline seed** (`user_credential.offline_seed`: an unkeyed Argon2id of the password, sealed, kept out of the audit log; the database refuses a password changed with its seed unchanged). An entry is Argon2id of the seed under a salt for that phone; a **mark** (a keyed fingerprint) goes stale when the password is set anew; `LOGIN_LIST_ENTRIES_PER_CALL` (50), `more`. The master passcode's check is made the same way **from its own sealed offline seed** (`master_passcode.offline_seed`, ADR-542; never from its verifier; none sent while a version has no seed yet) and sent with its version; `Device.masterPasscodeVersion` moves only as the device key's actor, never back. **A login list kept on a phone is outside both standards: ARCHITECTURE §7.2's safeguards are the user's accepted risk (ADR-105, 139).** `offline-checks.ts`, `phone-login-list.ts`. [449, 454]
- **An address for a phone's GPS:** `POST /phones/current/address-lookups` (`MONITOR_ON_PHONE`, the point in the body, never a URL): `{ address, noAddress }`, never a refusal (the monitor types it, ADR-111); nothing written, **neither point nor address logged**; the API alone asks the address server (`AddressServer`, `ADDRESS_LOOKUP_ANSWER_SECONDS` 5, 64 KiB); one reading for API and worker (`lookedUpAddress`). **A field event's address sent as `LOOKED_UP` takes the phone's word** (a reviewer corrects it like any field). [111, 455, 522]
- **`MasterPasscode`:** a version, its Argon2id PHC hash (a check holds it to that shape; keyed with the password key, ADR-542) and its sealed offline seed; a change is a new version, never an edit but to key the installer's verifier and write its seed, each once (`master_passcode_kept_once`); the API reads and inserts, the worker and viewers can't read it; the seed writes version 1 from a hash the installer hands it in memory. [281]
- **What a monitor never does on a phone:** pick pricing (never see a rate; rules create every transaction) or see a code: they pick **by name**: a unit rate **pay item** by its payable type after the crew photo, a load's or haul-out's **debris type** on Complete; a load carries no pay item, and its phones get none. **A record the monitor submitted is sealed for them** (the user, ADR-477): never reopened or edited on the phone, synced or not; one opened and not yet submitted stays theirs to adjust, for days if the work takes days, unflagged. **No edit log** (`FieldEventEdit` withdrawn, ADR-477); the device sends no change log. Disposal devices carry **no ticket list**; they trust the scan; cancelled tickets stay on the device, unsynced. [056, 071, 088, 124, 176, 207, 223, 477]
- **Printing on every project** (Zebra ZQ): two collection copies (or control ticket + stub), a disposal copy at disposal, haul-out and final disposal, unit rate always; barcode = the ticket number; receipts are never records. On a control-ticket project the disposal receipt may be handwritten on the back of the control ticket; haul-out prints at the collection side. **Capacity is never typed**, except a truck keyed in by hand (flagged, billed at the certification's capacity). **No check digit**; a tandem's truck and trailer carry unrelated ticket numbers; tandem cert numbers are usually, not always, consecutive; a trailer swap isn't flagged. [102, 114, 115, 154]
- **Certifying** is done on a phone set up for certifying, where there is signal; it gets a block of cert numbers (unless pre-printed numbers are typed). **Any phone with a connection can refresh its lists at any time.** [151]

- **Unit rate, on the field app** (`src/new-ticket.tsx`, `unit-rate.tsx`; `packages/domain`'s `PhoneUnitRate`; ADR-583): **the working crew is the crew of the monitor's newest unit rate ticket on the project on that phone**, kept nowhere else (the server keeps none, AC-04-70); New offers it first ("Same crew" or "Change crew"), else the crew's badge (never keyed in by hand), then the phone's next unit rate number, always made there, typed again; a crew isn't held to one open ticket. Complete: the crew shown and its photo; **the payable types each once, by name**; a field tag where the project has them; then **what `PhoneUnitRate` says the kind of work asks**, by the lists' kind of work (its count shape and built-in key, now sent): a count unless every pay item of the payable type is always one (whole unless one allows decimals); a tree measured around or across where one asks for it or has a band; Stumps by its key: the diameter two feet up, the root ball, "half or more exposed", the survey number; items with a count each; items with hours each, to the quarter hour. **The pay item is worked out from the bands as the work is entered** (`SizeBands`), kept for the receipt, **never shown, nor any rate**; "ineligible" asked only where the pay item worked out allows it (none worked out: any of the payable type's); an ROE where the phone holds them; one point; photos; the review, the crew first, **submitted "for crew N"**: its confirmation each time. A measurement goes with how it was read or not at all. *Agent defaults.* [583]
- **The forms that are no ticket's, on the field app** (`phone/forms.ts`, `src/forms.tsx`; `packages/domain`'s `PhoneSurveys`; ADR-584): the store's `forms` shelf holds **each form begun, its monitor's alone**, left at any step and finished from home's open list, cancelled kept unsent, **sealed at submit** (ADR-477: nothing a monitor does after changes it, C66); its time is when it was begun. **Every start is a list** (ADR-127): **an ROE** its number at New, the next of the phone's ROE block written `R-0007` (marked used as it opens) or the paper's own, **typed again either way**; **a survey** its work type from the firm's list, the `ROE` work type left to the ROE's button; **an incident** its type, then the firm's sub-type; **a drop-off log** nothing, opening at once at the assignment's site (none started with no site). The details: an ROE's parcel, owner, address and signed day; a survey's ROE (the lists' and those this phone made; **a post-work survey offered the ROEs whose pre-work survey is done**: the lists' and the pre-work surveys this phone made, `PhoneSurveys`, C118) and number as written; an incident's description and parties, then **only what the incident form offers** (AC-04-101); a drop-off's resident and origin. **"GPS required" is the ROE form's**: where set the ROE asks the place (the address looked up or typed), otherwise records none; every other form records its place, taken at submit where none was captured. **The firm's own fields** of the newest version the lists held when it was begun, each by its type; a required one unanswered holds Next, **never a photograph's**; a photograph field's answer is its own photograph's id; typed text bounded to what the record keeps (C127). **An ROE made on a phone carries no scope** (*agent default*): the back office enters it from the paper. *Agent defaults.* [584]
- **Certifying, on the field app** (`phone/certifications.ts`, `src/certify.tsx`; ADR-585): the store's `certifications` shelf holds **each certification begun, its monitor's alone**, left at any step and finished from home's open list, cancelled kept unsent with its number, **sealed at submit** with its five views after it; its time is when it was begun. **New: the number**, the next of the phone's cert-number block (marked used as it opens) or the pre-printed sheet's own (Q-142), **typed again either way**; one the lists already hold is said, never refused. Then a container or a crew; **the prime picked; a sub typed into tier 1 or 2, the prime's known subs of that tier offered as it is typed** (AC-03-14), the two tiers held to `CertificationSubs.check` before going on; the driver and the tag as the sheet has them (an expiry typed as 2026-10-09); the vehicle type of that kind picked or typed, a crew's crew type picked; **a container's boxes**: the primary, then each box's feature (picked or typed, required), shape, sign and **the measurements its shape holds** (`Capacity.measurementsOf`), whole inches; **the capacity worked out by the domain's `Capacity` as they are entered and shown, never typed or kept**, measurements that give none holding Next in the domain's words (data entry, as a quarter hour is); five views, one photograph each, taken again in its place, none required; **a helper picked from the lists' helpers** (AC-03-36), the representatives' names; a modified truck's replacement picked from the lists' certifications and this phone's, its reason held to `CertificationChanges.replacement`; the review once. **The record sends the boxes, each with `null` for every measurement its shape doesn't hold (C129), never a capacity; a crew's none**; a sub tidied of stray spaces. A refusal at the sync is shown on Sync in the server's words and kept (AC-11-42). *Agent defaults.* [585]
- **A phone away from its site** (`ticket-capture.tsx`; ADR-585, C118): an open ticket of work at a site whose fix at New lies outside the site's area as the lists hold it says so, by the domain's `SiteArea` (the project's circle round its GPS, or its own shape), **the same rule the worker's `OUTSIDE_SITE_AREA` flags by**; an advisory, never a refusal (AC-11-88). *Agent default.* [585]

### Phones: the passcode offline, out of service, turn-in — `adms-field-app`, `adms-exceptions`; ARCHITECTURE §7.2, §8 [134, 456…464, 487…490, 520, 530, 531]
- **An unplanned assignment reported** (`POST /phones/current/unplanned-assignments`, `PROVEN_PHONE`, nobody signed in, **no passcode sent**: the phone checked it): the phone's id for it, project, monitor, work, site, unit rate pay items, `madeAt`, `deviceUtcOffsetMinutes`, **`occasion`** (`SETUP`: a setup or **a site move**, a setup anew at another site; `MONITOR_SWITCH`: a switch to a monitor with none). `SAVED`, `ALREADY_SAVED` (the first stands) or `NOT_SAVED` with the domain's reason. **Kept as reported, never refused over eligibility** (an archived monitor, a closed project, a phone out of service). **Its day is the phone's clock's, in the project's time zone; three times kept** (`madeAt`, offset, `receivedAt`). Written as the master passcode's actor with `DEVICE_SETUP`/`DEVICE_SWITCH` and `MASTER_PASSCODE_USE` at the phone's time. **Nothing the dispatcher planned is changed from a phone**; what was set up on a phone stands over the board's plan for that phone that day (the user, ADR-459). A switch saved ends the earlier monitor's session on that phone. The standards' view: ADR-456 (a phone's word for an act done offline under a shared passcode: the user's accepted risks). [456…459, 462]
- **A session under the passcode, with a connection** (`POST /phones/current/passcode-sessions`): `AS_MONITOR` (the passcode for their password) or `TEMPORARY` (a roster monitor); a session row **marked** `masterPasscodeSession`, written as the passcode's actor, **no sign-in of the monitor's**; it ends any other on the phone; a temporary one ends at the project's day's end or the monitor's hours, whichever first. **Setup choices** (`POST /phones/current/setup-choices`, the passcode in the body): open projects, monitors in service (paged), an open project's live sites and unit rate pay items in service; never a rate, rule, description, load pay item, password, phone number or role; each read one `MASTER_PASSCODE_USE`. **Every other use a phone logged** (`POST /phones/current/passcode-uses`, no passcode sent): `MONITOR_SWITCH` (to a monitor with their own assignment), `SESSION_AS_MONITOR`, `TEMPORARY_SESSION`, `SIGN_IN_UNLOCK` (the phone's sign-in screen unlocked, one use naming nobody, ending nothing; ADR-576), `WRONG_TRY` (moves no count on the server), at the phone's time; the database lets a phone-reported security event be written only as the passcode's actor naming that phone. **A sign-in made offline** is reported at `POST /phones/current/offline-sign-ins` (`OWN_PASSWORD`, `AS_MONITOR`, `TEMPORARY`) with a proof (HMAC-SHA-256 over `OfflineSignInRules.signed`, keyed by the first slow hash of what was typed), checked against the monitor's offline seed or the passcode's own sealed seed (ADR-542), **never the phone's word**; taken, a session from when it was made; refused `401 SIGN_IN_REFUSED`, shown to the back office as `OFFLINE_SIGN_IN_REFUSED`. [462, 463, 464, 531]
- **A phone out of service is received, never refused** (ADR-134): at its next sync it proves itself and uploads; what it made after its removal time arrives flagged. **The door decides a phone's standing once a request** (`Admission`, `PhoneProofs.proven`): a phone out of service reaches only endpoints marked **`outOfServiceToo`** (its read of itself, its sync, a photograph's file read and sent, its two reports, its turn-in) and is `409 PHONE_OUT_OF_SERVICE` elsewhere, whatever session it holds. **It only sends:** its work received, no number block topped up (the database refuses it a new block, `number_block_key_standing_guard`), no passcode check, no lists. **What a phone sends is `PHONE_IN_USE`:** the monitor's session beside the phone's token, or **the master user** (the passcode beside the phone's proof; a security event); nobody signed in: `401 NOT_SIGNED_IN`. [134, 473, 531]
- **The back office's phone acts (Dispatch):** rename (`PATCH /phones/:deviceId`); remove (`POST …/removals`: `outOfServiceAt`, never after now nor before enrolment, a reason from the list's `PHONE_REMOVAL` use; a lost phone made retired); put a found one back (`…/returns`, a note); a revoked key's phone is enrolled anew. **A lost or retired phone's key is revoked by the worker after the firm's time** (`FirmSettings.phoneKeyRevokedAfterHours`, 24 as shipped or off; an admin or Setup; counted from `outOfServiceMarkedAt`): its issued blocks retired whole, `keyRevokedBy: FIRM_TIME`, `DEVICE_KEY_REVOKED`; the database allows only that. **Such a phone still proves itself with the passcode beside its key** (`MASTER_PASSCODE_NEEDED` without it) to sync and be turned in, nothing else. The firm's decision is ADR-520; the design *agent defaults*. Story: `lost-phone-key`. [520, 530, 531]
- **"Sync and turn in"** (`POST /phones/current/turn-ins`, `TurnIns`; `PROVEN_PHONE`, the passcode in the body; a phone out of service the same way): having synced and sent its files, the phone names everything it still holds by its ids and by fingerprint what it sent with no id the server could read, and each series' last number used (bounded). **Only when the server has all of it from that phone** (saved, quarantined or held and resolved by a person; its photographs with every file) is it turned in, in one piece of work: `MASTER_PASSCODE_USE`, `DEVICE_TURN_IN`; each series' blocks end (**reported: the unused rest handed back; not reported, or a lost phone: retired whole**, `TurnInRules`); a phone in service becomes `RETIRED`; its sessions end; **its key is revoked**; answered `wipe: true`. Otherwise only the use is logged and the answer names what is missing (`wipe: false`). The database lets only the turn-in revoke a key (besides the firm's time) and freezes a turned-in phone. **A client wipes only on `wipe: true`.** Every request of a proven phone is also counted for the phone. [065, 096, 134, 468, 487…490, 495, 526]

### Time, photographs and files — ARCHITECTURE §10–§11 [100, 101, 161, 181, 281, 478…486]
- **Each project has a time zone**; tickets and time-clock entries use it. The database checks it is an IANA name (an area and location, or `UTC`; never an abbreviation or an offset); no column is a time without its zone. **Offline, the device clock is the recorded time**; a field event's own times and offset are never checked at the door, only flagged later by reconciliation with a time message. Time clock: start, 30-min break at 6+ hours, clock-out, the day ends before midnight, **no cap on monitor hours**; the 12-hour flag is **crew hours only**. [100, 281]
- **A load's time is its collection's end** (haul-outs too); a disposal's time is its disposal's end. The active window, the *Ticket date* criterion and daily counts use the load's time: a Monday preload dumped Tuesday is Monday's, at Monday's rate. [161, 181]
- **Photographs:** shrink carefully at near-original quality, **keep depth data** (or store it linked), hash at capture, **keep indefinitely**. **At most 8 per ticket** (the phone's rule, never the database's); whether photos are **required** is a **pay item** setting; too few is flagged, never blocked (no minimum unless required, then 1). **A certification takes five**: operator with placard, interior/back, right, left, front. The record: one owner, two fingerprints, the file's place written once (Field events). [101, 157, 179, 181, 326]
- **Where a file is kept:** any S3-compatible store over HTTPS (`@aws-sdk/client-s3`, exact versions, ADR-479), **one bucket that keeps every version** (`adms-media` locally, made by `pnpm local:up`, never by the API). **The API's identity there may put and get an object in that bucket and nothing else** (no delete, no bucket made, no list, no setting changed; held by `apps/api/test/media-store.test.ts`). **`MediaStore`** (`apps/api/src/media/media-store.ts`): `keep` only where nothing is kept under the key (`KEPT` · `ALREADY_THERE`), `sizeOf`, `read` up to a bound; **no call deletes, moves, copies or lists**; an error never names the key, bucket or identity. Settings `ADMS_MEDIA_URL`, `_BUCKET`, `_REGION`, `_ACCESS_KEY`, `_SECRET_KEY`, `_CA_FILE`, `_ADDRESS`; `MEDIA_STORE_ANSWER_SECONDS` (30). *Agent defaults.* [478, 479, 480]
- **A photograph's record at a sync** (the sync's own part `photos`, after the records, at most 200): each read on its own and answered `SAVED`, `ALREADY_SAVED` or `NOT_SAVED`, **never quarantined**; what it is of (one of the seven kinds, by id), the view (a certification's), who, when, where, **both SHA-256 fingerprints (the phone's word, written once)** and a depth file's own `depthSha256`; **never the file's place, the file, an upload time or the phone.** **The server makes the place** (`projects/<project>/photos/<photograph>`, `.depth` beside it), never told to the phone. **A photograph whose record is held for a person is saved and kept with it** (`held_record_id`, its files taken); only one whose record is nowhere is held. One of a quarantined record belongs to that record. Saved, it joins the ledger and queues what reads it. *Agent defaults.* [481, 482, 526]
- **A photograph's files: the media endpoint** (`GET`/`PATCH /phones/current/photos/:photoId/files/:file`, `photo` or `depth`; `PHONE_IN_USE`, `outOfServiceToo`): **only the phone that took it, once its record is saved** (anyone else 404). Parts are `application/offset+octet-stream` with `offset` and `length` (tus 1.0's core), answered `KEPT`, `RECEIVING` (`received`) or `NOT_MATCHED`, never a place. **Unfinished parts live only in the API's memory** (`MEDIA_RECEIVING_BYTES_AT_MOST` 256 MiB across phones, the longest waiting let go). Checked first: a file ≤ `MEDIA_FILE_BYTES_AT_MOST` (32 MiB, 413), a part ≤ `MEDIA_PART_BYTES_AT_MOST` (4 MiB), the first bytes an image (JPEG, HEIC/HEIF, PNG, TIFF; `photoFileTypeOf`; else 415). **Whole, its SHA-256 against the record's: kept once, never overwritten, `uploadedAt`/`depthUploadedAt` written once under the device key's actor**; **a whole file that isn't the one fingerprinted is set aside, never turned away** (`<place>.set-aside/<SHA-256>`, a `set_aside_file` row; a person closes it, Sync). `RATE_LIMIT_FILE_PARTS_PER_PHONE` (300 a minute). **A client sends files only once the record is answered saved**, part by part from where the server says (`photoFileAnswerRead`, `photoFileGoesOnFrom`), held to it by `syncClientSuite`. A story's files are kept in memory (`StoryMedia`), never the stack's bucket. *Agent defaults.* [482, 483, 526]
- **The back office's read of a file** (`GET /photographs/:photoId/files/:file`; an admin, or a manager/analyst granted *view review*, ADR-539): the bytes under the type their first bytes say, `Content-Disposition: attachment`, sandboxed, `nosniff`, `no-store`; **its SHA-256 read again first: a file not the one fingerprinted is never handed back (500)**; logged with its reader, not audited. **A viewer reads a photograph's file** (`GET /viewer/photographs/:photoId/files/:file`) **only once the database has shown them its record** (through `$viewed`), then by the key they are never told, handed back the same way; one not shown is 404. **A kept map's file and a site shape's file are read back the same way** (`GET /map-versions/:id/files/:file`, `map` or `zones`; `GET /site-shapes/:id/file`), under the type kept with them (`answersFileOf: mapFileTypes`), the fingerprint the key names and the kind read again; a drawn one has none (404). Six endpoints answer a file, held exactly by the contracts' test. [483, 535]
- **A map's file** (`POST /projects/:projectId/map-files`, Setup's; the second endpoint that takes a file, its own route the user's, ADR-486): bytes ≤ `MAP_FILE_BYTES_AT_MOST` (16 MiB); a zip (shapefile, KMZ) or GeoJSON or KML by first bytes (`mapFileTypeOf`); read before anything is kept (`MapFileReader`, **read in a `worker_threads` thread of its own, bounded by `MAP_FILE_READ_SECONDS` (60) and `MAP_FILE_READ_MEMORY_MEBIBYTES` (512)**, a reading stopped or failed answered as a file that can't be read, ADR-548): a zip of at most `MAP_FILE_ENTRIES_AT_MOST` files, unzipped ≤ 64 MiB, a `.prj` read by proj4 and converted; a shape's rings bounded (`MAP_FILE_RING_PAIRS_AT_MOST`). **Kept only when a layer is a shape, once, by its SHA-256** at `projects/<project>/maps/<SHA-256>`. `…/map-files/:id/map-versions` loads a project map; `/sites/:siteId/map-files/:id/shapes` a site's next shape, each from the file as kept, its fingerprint checked again. An Esri feature layer is read by the server, its request held against SSRF, its token never kept. *Agent defaults.* [484, 485, 486, 524, 528, 529]

### Org model and project setup — `adms-data-model`, `adms-ticket-workflows` §4.0; `spec/DATA-MODEL.md` §2–§3 [023, 026, 303, 305]
- **`Client` → `DeclarationEvent` → `Project`.** Clients and declaration events are firm-wide shared records; a project names one client, one declaration event and one program type ("every project under this declaration" is one query across clients). [023, 026, 303]
- **Pick-lists are firm-extendable** (program types with "requires ROE", debris types added to a project's forms, vehicle types, features, payable types, reasons…; **no fee kinds**); picked, never typed. **Fixed in code:** ticket types, statuses, billing units, roles. Catalogue: `spec/LISTS.md`. **Reasons** (voiding, a typed ticket number, accepting a flag, a back-office record, a phone's removal) are picked from a firm list. [024, 070, 074, 173, 246, 530]
- **A project** has an **active window**, judged by each ticket's end time (a load's: its collection's end; outside it, flagged); a **ticket-number source** (control or generated); its enabled ticket types and unit rate sub-types; **load-call limits** as a project setting (flag at or under 5% and at or over 95% by default from `policy.env`, changeable or off; not a rule criterion; **a 0% load call is always flagged**); **"Allow split loads"** (ticked by default where the program type requires ROEs); the time clock (off until the firm switches it on). [018, 041, 056, 057, 064, 137, 161, 164, 181, 303, 304]
- **A closed project is closed** (the user, ADR-529): an admin closes it by hand, seeing first what is still open (phones not turned in, tickets not QC'd or not invoiced, records waiting for a person); **the database then refuses any change to it**; its assignments are withdrawn and its phones' unused numbers retired; anything a phone sends for it later is **held for a person**, never added; an admin reopens it with a reason, recorded. A project closed twice keeps its first close. [527, 529]
- **Several primes per project**, each with its own subs, **at most two tiers**, never shared between primes. **Subs are typed at certification** under the chosen prime (the phone suggests known ones); certifications naming alike subs are flagged `SUB_NAME_ALIKE` and a person corrects the sub (no merge). A contractor holds contact details as a client does. [081, 108, 305, 306, 529]
- **Contracts are simple:** a name, the prime, an optional link to the signed copy; the prime is on the project first. **A pay item holds a rate for each of several primes**, never a copy per prime. **A rule names one contract** and **runs only on tickets whose prime holds it** (no *Contractor* criterion needed for pricing; each prime still gets its own rules); a rule of only *Remove* / *Void* may leave it blank and runs on every ticket of its form (*agent default*). **A transaction takes the pay item's rate for the rule's contract's prime**; a ticket no rule of its prime prices is flagged ("Ticket 101010: no pricing rule on a Summit contract matches. Flagged for review."); a pay item with no rate for that prime writes a **$0 line**, flagged. **The payable type is the work; each pay item is a priced line of it** (same work at two rates by distance = two pay items, mileage rules). [146, 174, 206, 212, 239]
- **A disposal site is entered on each project that uses it** (never shared), with an **activation date** and optional **close date** (a disposal before it: "site not yet active"; after: "site closed", flagged); **a permit** (missing: flagged outstanding, never blocking); **its GPS when added**; and an **area**: standard, a circle round the GPS (built-in 200 m, one size per project in its GIS settings), or advanced, its own shape. A disposal whose end GPS is outside it is flagged; both haul-out ends are checked the same way; a changed size or shape is dated, kept and reprocesses un-invoiced tickets at that site. [111, 136, 142, 144, 145, 173, 181]
- **The project map:** a **boundary** and optional **zones**. **No monitor records a zone:** reconciliation tests the ticket's GPS against the map and **attaches** the zone; a collection or unit rate ticket outside the boundary is flagged, and one inside it in no zone. Maps come as **dated map versions** by upload (shapefile, GeoJSON, KML/KMZ) or an **Esri feature layer** (`POST /projects/:projectId/esri-map-versions`, "Refresh from Esri", `/sites/:siteId/esri-shapes`; every feature fetched as GeoJSON in WGS84 page by page before any database work, each copy kept as a map's file; `EsriLayers` holds the request against SSRF: the layer's own HTTPS address only, never a local, private or reserved address (checked where the connection is made) unless listed in `ADMS_ESRI_PRIVATE_HOSTS`, no redirect, bounded; a token sent in the body, never kept, logged or answered; KML parsed by `@tmcw/togeojson`, a `<!DOCTYPE` refused first). The worker checks at reconciliation, never the phone; a new version reprocesses un-invoiced tickets; each ticket records the version used. Drawing (site shapes, boundary, zones) downloads as zipped shapefile or GeoJSON; **the base map is our own**, no outside map company. The screens: Phase 4 (REQ-124b). [135, 136, 141, 142, 144, 311, 484, 485, 523, 527, 528]
- **Forms ("everything is a form", Q-103):** a project picks a form per document type (load, haul-out, unit rate ticket, truck certificate…); **debris types are added to a form** (with *Reduced*, reduction method, *Hidden on phones*) and **named as the contract names the work** (Mulch and Ash are two debris types on the haul-out form). *Reduced* is a helper for rules, reports and checks; reduction method is a firm list; *Hidden on phones* takes it off that form's phone list and tickets that have it keep it. Setup **warns** (never refuses) when an unreduced debris type is added to the haul-out form (`DebrisTypeEntries`). The day's assignment says which forms a person may make; "GPS required" is stated on the ROE form alone. [211, 214, 308, 529]
- **The firm's own fields:** fixed fields on anything that bills (tickets, certifications); **firm-added fields** (text, number, yes/no, list, photo) on surveys, ROE forms, incidents and drop-off logs, exported, never read by the engine or rules; free-text notes on everything. **Stored as** a versioned `FormDefinition` per project form (a change is a new version, never an edit) and **one JSONB answers column keyed by field ID** with the version answered, checked by a schema generated from the definition (`packages/contracts`), corrected and audited like any captured field. **Nothing the engine, a rule or a flag reads lives in JSONB** (promote it to a column by a migration). [160, 278, 308]
- **Field tags** (the legacy "Special Classes"): a project list the firm fills, starting empty; the collecting monitor picks one **optionally** on Complete, right after the debris type, and a unit rate ticket may take one (the tower doesn't); read only by the *Field tag* criterion and exports. **Incident sub-types start empty.** *Agent readings:* picked at a haul-out's loading end; on unit rate, on the review before the number. [137, 211, 216, 218, 234]
- **Cert-number blocks:** 100 per certifying phone, topped up at sync. [181]
- **Disposal sites** (the legacy "Location"): a **site type** (**TDSR/DMS · Final Disposal (FDS) · Transfer Station · Other**, firm-extendable; HHW is not a type; descriptive, and what *Disposal site type* tests) plus **facts that hold for every ticket type:** **Takes loads** (loads end there); **Haul-outs leave here** (only on a site of the built-in TDSR/DMS type; setup and the database refuse it elsewhere, and refuse changing a marked site's type, ADR-298, 311); **Charges a tipping fee** (the box tells the system, nothing on the pay item, ADR-220; ticking it leads the firm to write the site's tipping fee pay item there and then, with its rate per prime, and the fee rule *Add transaction #2*; the site keeps the link, which is how a fee line is told from a hauling line; **a site may keep several**, ADR-311, 312); **Ineligible site** (a load dumped there is flagged and still bills); plus the firm's own labels. The legacy *Critical* box is left out (ADR-219). A load that needs no load call measures its quantity **from the tickets it carries** (a pay item setting: stumps, white goods). [201, 205, 215, 219, 220, 298, 311, 312]
- **A ticket at a site without the matching fact is flagged, never refused** ("Ticket 101013: dumped at Old Quarry Pit, which isn't marked Takes loads. Flagged for review."). A load dumped where a tipping fee is charged with no line for its fee pay item is a **missing rule**, never a mismatch (ADR-222); checked on loads and haul-outs **dumped** there only. **A haul-out is reduced debris leaving a TDSR for a different site**, never back to the site it left, never from one final disposal site to another: a haul-out dumped at a TDSR is flagged and priced no further (ADR-226); one that left anything but a TDSR is always flagged (ADR-298). The system never guesses where debris is headed: it checks the debris was allowed to go where it went. Halves on different days (a preload, a haul-out from a prior date) are not flagged by default. *Agent reading:* drop-off logs aren't checked against the site's facts. [205, 222, 226, 298]
- **Every phone that works at a site is set up for that one site** (the tower; the haul-out collection at the TDSR; the haul-out disposal at the FDS; the drop-off log); the site fills in on every record; **no start list shows sites**; a curb collection phone has none. A phone **moves site offline**, each record keeping its site. **Master setup** can set a phone up for any work on the project, the monitor then reaching only that work; setup offers the project's active sites (*agent readings*). The user's account of an HHW site is kept for the HHW trail (KD-30, REQ-518). [188, 190, 193, 194, 195, 201, 205]

### Certification — `adms-certifications` [015…017, 045, 076…082, 318, 320, 321, 328…330]
- **It certifies a container or a crew, never a vehicle.** **One number:** cert = placard = badge, pre-printed or system-issued, **unique per project only** (the user, ADR-318: the same number on two projects is ordinary, never flagged or refused; the golden mission's P2 has its own `730416`). [015, 016, 017, 045, 056, 102, 318]

A measuring mistake is corrected in place and its tickets reprocess. [079, 082, 153, 289]

Representatives are names only. Its photographs reach the store through `POST /photographs` (below). [080, 294, 521, 534]

### Field events and the records beside them — `adms-domain` §1.2, `adms-ticket-workflows`; `spec/DATA-MODEL.md` §4 [236, 238, 324…327, 332]
- **A field event** is one monitor's record of one thing witnessed at one place and time, under a ticket number: collection `COL`, disposal `DIS`, haul-out collection `HOC`, haul-out disposal `HOD`, unit rate `URT`. **A ticket is its number and the events under it** (project + workflow + bare number). The first event makes the number and the truck carries it to the second. **Each workflow, fixed in code:** load `COL` → `DIS` (quantity at the disposal; a split has one `COL` per suffix); haul-out `HOC` → `HOD` (quantity at the TDSR end; the disposal confirms it dumped and left empty); unit rate, one `URT`. One event of each kind per ticket; another is the duplicate quarantined at sync. [236]
- **The completed load and haul-out, statuses, flags, zone, mileage and transactions are not events:** the worker draws them from the ticket's current events and setup, alone, and again on every reprocess. **Event-driven, not event-sourced** (*agent default*): corrections stay in place with the prior value in `AuditRecord`; no correction events, no replayed log. **Forms and certifications are records, not a ticket's events.** Never a bare "event" where the declaration event could be meant. Code: `FieldEvent.kind` `COLLECTION` · `DISPOSAL` · `HAUL_OUT_COLLECTION` · `HAUL_OUT_DISPOSAL` · `UNIT_RATE`; derived `CompletedLoad`, `CompletedHaulOut`. An outside design review was weighed: only the event idea taken (ADR-238). [236, 238]
- **What every field event records** (DATA-MODEL §4.1): **its source** (`DEVICE`: its phone, assignment and setup version, no back-office person or reason; `BACK_OFFICE`: the person and a reason from the firm's list, no phone; the system actor creates none, C44); **the number**, whether typed and the reason picked (a reason on a scanned number is refused; **a typed number with no reason is taken**); **the cert number as scanned** (always, a snapshot), the certification found (its own project's, empty until one has that number), keyed in by hand with a typed capacity (only then); **the site**, its own project's (a curb collection has none); **GPS at both ends**, a whole fix on the earth or none, no accuracy; **the address** and whether `LOOKED_UP` or typed; notes; whether made in a temporary session, and **which way a session under the master passcode was opened** (`masterPasscodeSession`: `AS_MONITOR` or `TEMPORARY`, none in a monitor's own; only on a phone's record; `TEMPORARY` exactly when `temporarySession`; the phone sends it in place of `temporarySession`, ADR-534 (11); AC-02-42). **No new required column has a database default.** **No driver, contractor, zone, destination or rate on a field event.** **Not checked, on purpose** (flags, or nothing): a number's digits, times in order, the certification found bearing the number scanned, a load on a container's certification, the site against the assignment's. *Agent defaults, but the C44 check, approved in DATA-MODEL §8.* [324]
- **What each kind records** (DATA-MODEL §4.1 (2)); **none is required on any kind** (a pick that didn't reach the server is a flag's). **The database refuses a detail on a kind that doesn't record it** (a debris type on unit rate work; a field tag at a tower or a haul-out's final site; an ROE number off a collection or unit rate; an estimate off a collection; a carried count off a disposal; unit rate's details off unit rate work). **A debris type is the entry on the field event's own project's form for its workflow**; a field tag and a pay item are its own project's. **A split suffix is capital letters (`A`… `AA`), only on a collection or a haul-out collection**; a collection has its suffix and its estimate both or neither; a pile gives a load call, never an estimate. A measurement says circumference or diameter (`MeasuredAs`). **`FieldEventItem`** (an itemised unit rate event's lines) and **`CarriedTicket`** (the numbers a load's collection lists, as written, never a link) sit only on their kind; a correction takes one off by `archivedAt`. **The rule lives once:** `packages/domain`'s `fieldEventDetails`, asked by `packages/contracts`' `fieldEventDetailsSchema`; a database test holds the database to the same table. *Agent defaults.* [325, 364]
- **`ScaleReceipt`** (DATA-MODEL §4.2): its own record, apart from any ticket; the number **exactly as written, never unique** (the user, ADR-328: a receipt book starts again at 001; a duplicate record is the worker's to flag); its site its own project's; who entered it (never the system actor), when, which phone. **Every weight is what the paper says**: all four may be missing, none worked out from another, a net of nought or below kept for a flag; only a gross or tare below nought refused. `FieldEvent.scaleReceiptId` only on a disposal or haul-out disposal of its own project; a load call or count beside it is taken. **A tandem weighed once is one receipt both disposals point at**; no field event holds a weight, no share sits on the receipt. [326, 328, 331]
- **`Photo`** (DATA-MODEL §4.4): the record only; **exactly one owner of its own project** (a field event, a certification, a scale receipt, an ROE, a survey, an incident, a drop-off log, or a quarantined/held record); a **view** (`PhotoView`, the five) only on a certification's; when, where, the phone; **two fingerprints and two places, all four written once** (a trigger refuses any change). **The back office's two marks:** `archivedAt` (removed from the record; the row, file and fingerprints stay; cleared to put it back) and `label` (the firm's words). **A removed photograph counts for nothing a record must have** (the user, ADR-345). **The database counts no photographs.** Viewers never see where a file is kept. **Added in the back office** (ADR-534 (2)): `POST /photographs`, the third endpoint that takes a file, sent whole (at most `MEDIA_FILE_BYTES_AT_MOST`), only onto a record made in the back office, a view only a certification's; its fingerprints the server's reading of its bytes, no phone, its upload time a person's from the back office alone (`photo_upload_guard`). [326, 329, 337, 345, 526, 534]
- **`Roe`** is configuration (ADR-294): edited by the API, audited, never deleted, no archive; its number (issued `R-0007`, or typed off the paper) not blank and once per project; only number, `signed`, `answers` and `source` required; no setup version. **`RoeScopeItem`**: one of a debris type (an entry of its project's load form) or a payable type, each once per ROE, an optional count. **`Survey`, `Incident`, `DropOffLog`** are evidence with no status and no worker column ("its time" is `madeAt`); a phone's or the back office's by one check; **an incident may name the contractor involved, a cert number and an ROE number**, each optional (`incidentOffers` says which a monitor is offered); a survey's number typed as written, never issued. **The firm's own fields:** `answers` an object with its definition, form and document type all or none; **no definition means `{}`**; checked by `packages/contracts`' `formAnswersSchema(fields)`. `FieldEvent.roeId` only on a collection or unit rate event, not held to match `roeNumber`. **Not checked, on purpose** (flags): an unsigned or missing ROE, work out of scope, a post-work survey with no pre-work survey. *Agent defaults.* [293, 294, 327, 328, 334]

[210, 332]

A record no phone of ours makes reaches the server through `handOver`. [332, 581]

A back-office field event has none. [571, 581]

### Tickets, numbers and the four workflows — `adms-ticket-workflows`, `adms-exceptions` [013, 027, 046, 056, 062, 065, 207, 209, 213, 221, 223, 243, 323, 571, 573]
- **`NumberBlock`:** device, project, series (`LOAD` · `HAUL_OUT` · `UNIT_RATE` · `CERTIFICATION`), first, last, last used, `ISSUED` · `RECLAIMED` · `RETIRED`; the series, the allocator and the refusal of overlapping blocks are built. [281, 323]
- **Two field events per load, two witnesses.** The load call is on the **disposal** for a standard load and on the **collection** for a haul-out. One truck has one open load at a time. **A refused load is not recorded**; a load dumps once and has **one** disposal. [013, 027, 155]
- **Numbers are bare**, in a **per-project series per workflow** (load, haul-out, unit rate), 100,001 to 9,999,999, unique per project; `COL`/`DIS`/`CLT`/`HOC`/`HOD`/`CHO`/`URT` labels are **display only**. Generated numbers come from device blocks, reclaimed on reset; control tickets use pre-entered ranges. [046, 056, 062, 065]
- **Numbering as built:** `ProjectNumberSeries` (one per project and series: `LOAD` · `HAUL_OUT` · `UNIT_RATE` · `CERTIFICATION` · `ROE`; first number, next never handed out) and `ControlRange` (loads and haul-outs only; two of one series never share a number). A generated project has a series per workflow; a control-ticket project only the unit rate series; either an ROE series from 1; a cert-number series once the firm seeds it (else cert numbers are typed). **Two phones never hold the same number:** `number_blocks_never_overlap` keeps apart what blocks hold (an issued or retired block its whole run; **a reclaimed block only what its phone used**, its unused rest cut again once, ADR-065). Rules: `packages/domain`'s `numbers.ts` (`NumberSeriesRules`, `NumberSeriesBook`, `PhoneNumbers`, `ControlRanges`, `NewProjectNumbers`); the allocator `NumberAllocator` (`topUp`, `reclaim`, `retire`, `next`). **Block sizes are policy values:** 1,000 ticket numbers, 100 cert numbers, 100 ROE numbers. **A top-up brings a phone to a full block of unused numbers at every sync.** A phone-made ROE's number is written `R-0007` (written, never parsed). *Agent defaults.* [323, 505]
- **Splits:** N collections → 1 disposal, grouped on the base number; the first is **`-A`**, never bare. Each property's share = its estimate ÷ Σ estimates, applied to CY or tonnage; no divergence check. **Rules run once per property**, on its share (its own zone, address, mileage; the load's cert, disposal and load call; *Volume* = its share). [032, 033, 055, 064, 162, 173]
- **Split haul-outs** (where the project allows split loads): N haul-out collections → 1 haul-out disposal, one collection per **pile** at the TDSR (debris kept apart by where it came from), `-A`, `-B`… Each gives the **load call so far**; the last is the haul-out's. A pile's part is what it added (10%, 35%, 85% → 10, 25, 50); its CY = capacity × its part; its share of a scale weight = its part ÷ the last call. **Rules run once per pile.** A pile is told by its debris type and field tag; a call not higher than the one before is flagged (`PILE_CALL_NOT_HIGHER`) and nothing bills; the load-call limits judge only the last call (*agent defaults*). A truck and trailer hauled out and weighed once are split by capacity, flagged and marked as shares. **Paid by the CY or by the scale's weight, as the firm's setup says** (the user, as a firm): the pay item's Unit of Measure decides and the firm's rules pick it; the load calls set the shares either way. In the golden mission: ticket **201004** (110 CY, calls 10/35/85%, 24.00 tons → 2.82, 7.06, 14.12 tons, three `MULCH-HO-TN` lines at $20.00, $480.00). [295, 296, 297]
- **ROEs** are records like tickets: made on a phone (offline) or in the back office; number, parcel ID, address, owner, signed + date, **scope**, a photo of the signed form. On an ROE-required project **every collection, unit rate ticket and survey carries one**. A **post-work survey links to its pre-work survey by ROE number** (flagged if none). A phone-made ROE takes a number from the phone's block unless the paper has one (typed). Its **scope** is picked from what the project has (its load form's debris types, its unit rate payable types, each with an optional count, recorded, never checked); a ticket whose debris type or payable type isn't among them is flagged (`ROE_OUT_OF_SCOPE`); no picks, no scope check. "GPS required" is a setting on the ROE form. [149, 150, 181, 293]
- **Unit rate:** after the crew badge and crew photo, the monitor picks the **pay item** being done **by name**, never a code: the list shows **each payable type once** (Leaners, Hangers, Stumps); the monitor measures; **the phone works out the pay item** from the pay items' size bands and prints it. **Each unit rate ticket carries one pay item**; the ticket keeps the pick and the pay item; **reconciliation works it out again from the bands**, so a corrected measurement moves it on reprocess (the phone's answer printed, the engine's bills); **no band → no pay item, flagged**; bands of one payable type can't overlap (setup refuses), a gap warns. [207, 213, 217]
- **Itemised work:** details (washer, dryer; skid steer, truck) sit inside one pay item and are **not** pay items; capture shape ≠ billing basis. Itemised lists: white goods, HHW, **crew time as item + hours**; HHW pounds are entered as the count. **Each unit rate pay item names its kind of work** (Hangers, White Goods, Crew time…), which picks the screen and the item names. White goods bill the **total of payable items**, **per item removed, not by type**; crew time bills the **highest item's hours**, once; kinds never mix on a ticket. **Rules** say which items count toward which pay item (*Item* criterion, *Quantity from*); a pay item with no rate writes a **$0 line** (staged freon: only the $0 line, then `WG-RMV-EA` + `WG-FRN-EA` when removed later, not double billing; `spec/RULES.md` §9). [040, 054, 084, 124, 126, 127, 128, 131, 132]
- **Measurement:** a standing tree at chest height before it's cut; the monitor records **circumference or diameter**; rules test the **diameter** (circumference ÷ 3.14, half up to a tenth); an already-cut tree's diameter, with photos, is eligible; QC checks the photo. One per ticket (a hanger: limbs of 2 in or more); "Measurement required" is a pay item setting. On a payable type's only pay item, a ticket measured under or over its band is flagged. **"Monitor may mark ineligible"** (a pay item setting) lets the monitor mark the work ineligible, flagged; otherwise monitors document only work they believe eligible. **Crew time:** several tickets a day per crew; the 12-hour check adds each item's hours over the crew's day; overlapping crew-time tickets are flagged. The crew badge stays on the phone until the monitor changes crew. [111, 158, 159, 210, 213]
- **Stumps:** CY = [(D² × 0.7854) × 24 + ((3.6 D)² × 0.7854) × 31] ÷ 46,656, D = the diameter two feet up (USACE Stump Conversion Guide; the ticket records only D; CY half up to one decimal: 30 in → 6.5 CY). **A stump is two pieces of paid work, extraction and debris removal**, each the firm's own pay items and rules; **paid as the contract says, never from the stump's CY** (the user's example: extraction EACH by size class of D, fill per CY; one ticket per stump). **Under 24 in is not an eligible stump** (flagged, never refused); no maximum; **no circumference**. **The stump ticket is a unit rate ticket, kind of work Stumps** (built in): D, root-ball diameter, "half or more exposed", **no hole depth**, the survey number (none: flagged). **Fill CY = 0.7854 × root ball² × 31 ÷ 46,656**, half up to a tenth (31 in a project setting); a rule pays from **the stump (1 each) or the fill CY, never the stump CY**; no root-ball criteria; no root ball, no fill line. **Two built-in stump checks** (on by default, per project): root ball wider than the stump; fill paid but not half exposed (both still bill). A smaller stump goes out as ordinary vegetative debris. [177, 178, 183, 187, 189, 192, 196, 198, 199, 203]
- **A load of stumps is an ordinary load whose pay item measures quantity "from the stumps":** never called or weighed; the stump ticket's number is painted on each stump and the loading monitor adds each by that number (no match, or on another load: flagged); the tower counts and confirms (mismatch flagged); CY = each stump's CY to a tenth, added. Whether it bills its CY is the firm's rules (a hauling pay item, or $0 where the per-stump price covers transport). **Demolition** is ordinary debris work by the CY on a project named for it. **White goods priced by destination** ride a load whose quantity comes **from the tickets it carries**: paid once, on the load, at the mileage band's rate; the curb ticket's own lines (freon) are the firm's rules; the tower counts the tickets (ADR-370). "White Goods" is a debris type the firm adds; nothing groups types. [200, 201, 204, 215, 218]
- **Every start on the phone** (ticket, incident, form) is **start → pick from a list → maybe a sub-list → details**, each list from project setup. **The order (ADR-209 as amended by ADR-571, the user):** every phone opens on one home screen; **New** takes the **badge scan, then the ticket number** (the control ticket scanned, or the phone's next generated number shown), **typed again by hand only where a person copied it** (a number the phone made, or one typed because the barcode won't read; never after a scan; the two must match, ADR-573), and opens the ticket, which waits in home's **open list** while the truck loads; **Complete** takes the details; the receipt prints at submit. **A ticket is left at any step and finished later**, what was entered kept on the phone across sign-outs and restarts; a phone holds several open tickets, each shown by its truck and number, nothing open is sent, submitting seals it (ADR-477). **One open ticket per truck on a phone:** a badge (or a hand-keyed truck) whose truck has one open opens it rather than a second, never an eligibility check (across phones the server flags overlap, ADR-027). *Agent readings and defaults (ADR-571):* the tower and the haul-out's disposal scan the driver's ticket at New the same way; unit rate generates its number at New after the crew badge; a split chain is its truck's one open ticket; a unit rate crew isn't held to one; a cancelled ticket keeps its number unsent (a generated one never issued again) and is left out of the phone's own duplicate check. **Collections take waypoints** ("Mark waypoint": the time and whatever fix, in order; at most a policy number; nothing in the engine reads them; their record and sync are 3.5.1's server half). **Photos at any step** while open, New included, at most 8; the review shows the photos themselves; before submitting one may be retaken or removed. **The truck's scanned information, not the monitor's pick, decides whose work it is** (ADR-186). **Both events pick the debris type**; a difference is flagged "debris type mismatch". Surveys/ROE start with the work type (Pre-work · Post-work · ROE); incidents with type, then sub-type. "Normal or split" is asked only where the project allows split loads. **No confirmation after each value**; the review screen shows everything once (ADR-573). [127, 137, 186, 207, 209, 211, 571, 573]
- **A load asks for one quantity, never both:** a load call, or the scale weight where the pay item the firm's rules pay it at is by weight (its Unit of Measure). **No phone knows which pay item a load is paid at** (its miles are known only after sync); its capture settings stay on the pay item; the site doesn't own weighing; fees never make a phone ask for anything. **What a site's phones ask for is worked out ahead from the rules on that form that could match there** (tipping fee pay items left out), **following the truck's prime**: all per ton or pound → the scale receipt instead of a load call; all "from the tickets it carries" → a **count**; anything else → the load call (the site's **quantity lookup**, carried in the phone's lists, shown on the site's page). The tower holds no ticket list: the worker compares its count with the collection's carried tickets. A weight-paid haul-out keeps its loading-end load call, unbilled. A Final Disposal tower offers the receipt number as an optional field (*agent default*); **as built, every tower offers the scale receipt beside a load call or nothing more, never asks it** (ADR-582). **What a phone at a site asks is one rule** (`PhoneQuantityAsks`, field app and harness alike): a haul-out's collection always the load call; a disposal or haul-out disposal its site's row for the debris type and the truck's prime; a prime unknown, every prime's rows where they agree; **no row held (lists of another site, C182) the lookup's own no-rule answer, the load call or nothing more, said as not held**; never another quantity. [213, 221, 223, 224, 227, 243, 582]
- **Capture:** the collection address from "Get GPS" then "Get address info" (looked up if online, else street number and name typed); a typed ticket number is flagged and needs a reason; **the load call is typed** as a whole number 0–100, never prompted; **0 is accepted, flagged and bills nothing**. [111, 116]

### Reconciliation, flags and the engine — `adms-validation`, `adms-exceptions`; `spec/FLAGS.md` [019, 021, 022, 030, 052, 060, 340…352]
- **Offline all day; arrival order means nothing; order by field time;** load comes in bursts. **Group by project + workflow + base number**; type is never used to *find* a pair. [019, 030, 033, 062]
- **Flag, never block.** Messages are plain facts ("Ticket 101008: debris type mismatch. Flagged for review."). The only sync rejection is a duplicate number, quarantined in full. [021, 022, 052]
- **Statuses: `PENDING | COMPLETED | MANUAL_REVIEW | VOID`. Review still bills.** A void stops billing; made by a person with a reason (a **Void ticket** button) or by a rule's **Void ticket** action, which names the rule. **A rule's void always wins:** an unvoid lasts until the next reprocess; to keep it, correct the data or the rule. [060, 118, 167]
- **No ageing:** an unpartnered event never expires; preloads are normal; only impossible timing is flagged. A `PENDING` ticket shows the flags of the field events it has, and stays `PENDING` until whole (*agent default*). Cert validity is judged at **work time** (the field event's end), and a failure flags. [048, 053, 079, 244, 344]
- **GPS checks:** a disposal's end GPS against its site; the project **boundary** replaces the dropped 5 km collection route check; "zones differ" and a split's "same zone" are dropped: a load's zone is its collection's. **Where it went:** a load dumped at a site not marked *Takes loads*, or a haul-out leaving one not marked *Haul-outs leave here*, is flagged; at an ineligible site, flagged and bills; at a tipping-fee site with no line for its fee pay item, a missing rule ("Ticket 101011: dumped at Bayline County Landfill, which charges a tipping fee, but no rule on this project gives it one. Flagged for review."); a line whose pay item needs a quantity the load lacks is flagged ("Ticket 101012: TIP-FEE-TN-BCL is priced per ton, but the load has no scale weight."). [135, 136, 141, 205, 215, 222, 223]
- **Mileage is the road route:** the shortest route on public roads open to ordinary traffic (no truck size) from the collection's end GPS (a load's or a haul-out's collection) to **the disposal site's own GPS** (ADR-208), from our own routing server (Valhalla). The worker **snaps** the collection's GPS to the nearest road point (its address from Nominatim) and routes from there; **no route found: the straight line, flagged** "no road route found". Never water. A split's mileage is per property. Computed by the worker before pricing. [110, 119, 162, 163, 208]
- **The worker's run** (`apps/worker/src/reconciliation/`, `Reconciliation.waitingJobs`; answers `{ runId, ticketsDone, ticketsFailed, tickets, pending }`): **one run per project at a time** (a Postgres advisory lock held for the run). **It reads the whole project once** (`ProjectRead`: every field event not void, the setup, what was concluded before) and works the tickets its jobs name. **One ticket is one `db.$write` as the system actor** (`TicketWork` concludes, `TicketWrite` writes): the worker's columns on its field events, its completed load or haul-out (updated in place; marked dissolved while the ticket isn't whole, un-marked when it is), its flags through `Flags.compared`, the run's decision. **Only what differs is written** (a run over unchanged input writes its run and decisions, no other audit record). **A ticket that errors** gets `NOT_PROCESSED` and a decision with the error, its status and earlier conclusions kept; it clears when next worked. **The worker never states a person** (who asked is the run's `requestedById`). A kept mileage stands until the audit log says an end moved (`MileageStanding`). **Flags on no ticket** (a certification's views, a site's permit, a survey's) are checked every run; a flag on a number no field event is under any longer is cleared. A load bills from the certification its disposal scanned; a haul-out from the one scanned at the loading end. *Agent defaults.* [352, 503]
- **The derived records** (only the worker's login writes; the API reads; nobody deletes): `CompletedLoad` (one per disposal event for its life; quantity source, capacity, load call, volume, weight and whether a share, carried count, `dissolvedAt`), `CompletedLoadCollection` (a row per collection: suffix, share, volume, weight, mileage with its source, road point, map data), `CompletedHaulOut`/`…Collection` (with `pileLoadCall`), `Flag` (`FlagCode` held to `spec/FLAGS.md` by a test; message; facts with their SHA-256; `FlagBilling`; the line's # and pay item; raised and cleared), `ReconciliationRun`, `ReconciliationDecision`; on a field event the worker's `zoneId`, `mapVersionId`, `workedOutPayItemId`, status and run time, nothing captured. **A load can't be concluded twice** (exclusion constraints `WHERE dissolved_at IS NULL`, never partial unique indexes, which Prisma would drop). Whatever a derived record names is its own project's. Viewers (client, auditor) see completed records, rows and flags, **no viewer a run or its decisions**. *Agent defaults.* [340]
- **Grouping and status** (`packages/domain/src/tickets.ts`, `Tickets`): tickets on **project, workflow and the number as recorded** (suffix apart), the same whatever order; `Ticket.status(raisedFlags)`: `PENDING` while a field event is missing; whole, `MANUAL_REVIEW` while any raised flag isn't accepted, else `COMPLETED`; `VOID` is never the worker's. Whole = at least one collection and the disposal (a unit rate ticket its one event); a second field event of one kind is an error, never a pick; suffixes A…Z, AA…; **a field event whose number isn't digits is in no ticket** (`NOT_A_TICKET_NUMBER`). What a flag does to the money is never read for the status. *Agent defaults.* [341]
- **Quantities** (`packages/domain/src/quantities.ts`, exact decimals as text, no floating point): `LoadQuantities`, `HaulOutQuantities`, `ScaleWeight` (net tons as written, else net pounds, else gross less tare; **usable only above nought**; `.sharedBy` splits one weight by certified capacity, each marked a share), `StumpQuantities`, `CarriedTickets`, `quantityFor(payItem, figures)`. **Shares are rounded half up and what is left goes to the largest, the last of equals.** **Which figure bills is the paying pay item's to say** (its Unit of Measure, its *quantity from the tickets it carries*); `quantitySource` only describes what the tower took. Where shares can't be worked out the whole keeps its figures and no property or pile gets one. It raises no flag. *Agent defaults.* [343]
- **The flag catalogue** (`spec/FLAGS.md`; `packages/domain/src/flags.ts`: `flagCodes`, `flagBillings`, `new Flags(timeZone).raise(code, subject, told, facts[, fieldEventId])`): **a new check raises a flag only through it**, the message *told* (names, times) apart from the *facts* kept (ids, numbers, days, ISO instants), so a renamed site changes no flag; **a flag is the same flag when its code, field event and facts' hash are** (`Flags.compared` → kept, cleared, raised). **A new flag is a row on the page, a code in `flagCodes` and `FlagCode` (a migration), an entry in `flags.ts` and an example in `packages/scenarios/test/flag-catalogue.test.ts`.** §3.13's two (ADR-543, approved by the user, ADR-551): `MONITOR_NOT_SIGNED_IN` (a phone's record naming somebody who didn't hold the phone then, from the sync's answer) and `ASSIGNMENT_OF_ANOTHER_PERSON` (under somebody else's assignment); both bill. The count is the page's. `ProjectClock` answers every day, date and time in the project's time zone; messages' dates `03-Feb-2027` and 24-hour times, project time. [290, 344]
- **The checks** (`packages/domain`): `TicketChecks` (time, certification, the window; the work time is the field event's end; a tag good through its expiry date; replaced means after the new certification's certified instant; certification flags per field event; `OVERLAPPING_LOADS` on loads not void, raised on both tickets: the one the truck dumped under is `MANUAL_REVIEW` and bills, the phantom `PENDING` until voided, the user, ADR-339, 342; `SPLIT_SUFFIX_GAP` once whole; `DEVICE_CLOCK_OFF`); `PlaceChecks` and `SiteChecks` (`place.ts`; distance only by `geodesic.ts`, Karney's WGS84 geodesic, a point on the circle inside; boundary then zones, the zone and map version attached; no map, nothing raised; a point in two zones is in the first; a haul-out's collection takes no zone; a site open on its activation and close dates themselves); `QuantityChecks` (the ticket's load call against 0% and the limits; a receipt with no weight at all is a lineage token, not flagged; one weight shared; a carried ticket not found or on another load, **both loads flagged**; `SCALE_NET_DISAGREES` and `TWO_QUANTITIES`, the user's words, ADR-348); `UnitRateChecks` (**the worker's own pay item** by `SizeBands.payItemFor`; `NO_SIZE_BAND`, `OUTSIDE_SIZE_BAND`; the worked-out pay item's settings; `MARKED_INELIGIBLE`; *Count is always 1* raises nothing; the stump checks on key `STUMPS`; crew hours over `CREW_DAY_HOURS` on the ticket that takes it over and each later one that day); `RoeChecks` (only where the program type requires ROEs; a ticket's ROE flag puts it in review and it still bills; a survey's flags sit on the survey). **§3.10, a record that should not have been possible** (the user, ADR-345: "make them flag"): `DETAIL_MISSING`, `TYPED_NUMBER_NO_REASON`, `WRONG_KIND_OF_BADGE`, `GPS_UNREADABLE`, `NOT_A_TICKET_NUMBER`, `ENDED_BEFORE_STARTED`, `SPLIT_NOT_ALLOWED`, `OUTSIDE_CONTROL_RANGES`, `ASSIGNMENT_ON_ANOTHER_PROJECT`. **Whatever a record must have is counted from what is on it now:** a removed photograph counts for nothing. *Agent defaults but the user's flags.* [342, 344…348]
- **Mileage** (`packages/domain/src/mileage.ts`, `Mileage`; the asking is the worker's, `apps/worker/src/mileage/`, `MapServers`, `Mileages`): **the route is asked by distance as a car drives it, never the server's plain `shortest`**, so it crosses no private road or farm track (the user, ADR-350); nothing keeps a mileage's two ends (they are the records'); **a map server that doesn't answer throws; only "no road" and "no path" are the straight line**. Tests stand on the example world's points on the pinned extract (`spec/CONVENTIONS.md` §6). **Mileage is shown with the transactions** (the user): each exported line shows its mileage and how measured, read from its collection row, never stored twice. [349, 350, 351]

### Review, QC, the lock and corrections — `adms-exceptions`, `adms-validation`; parts 8–9 [028, 039, 051, 086, 107, 166, 245, 362…369, 430…433]
- **QC status is separate:** QC Review → **QC Approved / QC Issues / QC Void**, set by hand; the back office's own mark, it never changes the record or re-runs reconciliation. **Only QC Approved tickets can be locked as invoiced.** For loads and haul-outs only the completed load (`CLT`/`CHO`, a split included) is QC'd and locked, never a single event; unit rate tickets, incidents, certifications and forms are QC'd on their own. QC status, the invoice lock and a flag's acceptance are **their own records**, so the API never updates a derived row and a reprocess can't lose one (*agent default*). [107, 117, 121, 168, 245]
- **Accepting a flag:** a reviewer accepts a flag that's right as it is, with a reason, audited; it isn't raised again unless its facts change. All flags fixed or accepted → `COMPLETED`. ***Accept flags* is a grant of its own; *correct* doesn't carry it** (the user, ADR-365, superseding ADR-166's last clause). [166, 365]
- **Corrections:** a permitted user may fix **any captured field** in place (audited), including renumbering. **Void is for work that never happened (never renumber a phantom)**; unvoid is an audited override. Any ticket, **completed ones included**, is then reprocessed; the engine updates its existing reconciled record. Reconciled records are system-only. [028, 039, 051, 086]
- **People's marks** (`packages/db/prisma/schema/marks.prisma`: `QcMark`, `InvoiceLock`, `InvoiceBatch`, `FlagAcceptance`, `TicketVoid`, `TicketUnvoid`): each its own record, written by the API for a person (`guard_table` `MARK`), read by the worker, never deleted, repeating its project. **A QC mark** on one of eight things (completed load or haul-out, unit rate ticket, certification, ROE, survey, incident, drop-off log), one each, a change of status the same row, no row is QC Review; QC Void on a certification does nothing to its tickets. **An invoice lock:** one in force per ticket, its unlock on its own row (who, when, an optional note); locking again is a new row. **An invoice batch:** a name used once on its project, never blank, renamed freely, never archived. **A flag's acceptance:** once for a flag, with a reason; the flag never changed. **A person's void:** project, workflow, number, a reason; one in force per ticket; **an unvoid always leaves its own record** (`TicketUnvoid`, the user, ADR-366). What a mark is on, who made it and when never change; a lock unlocked and a void lifted are history. Viewers: client and auditor every mark; a contractor user its own tickets' locks and their batches; no viewer an unlock's note. *Agent defaults.* [363, 365, 366]
- **The review services** (`apps/api/src/review/`; each reads the grant itself: an admin every action, a manager/analyst only with its live grant; rules `packages/domain/src/review.ts`): **`Corrections`** (any captured field of a field event but its number; a renumber (`RENUMBER`); an item line; a carried ticket; a photograph's two marks; a scale receipt; an ROE and its scope; a survey, incident, drop-off log; a certification's box, measured again by `Certifications.measured`); **a correction and a renumber ask for no reason** and take a note kept in the audit record; **a renumber is refused only what can't be a number, and a number held**, never for being a wrong choice; taken off is a mark (`archivedAt`). **Since task 2.8.7 every captured field is correctable** (ADR-534): an ROE's number (refused where another holds it; **a number finds its record**: what names the new number points at it, what named the old one at none; snapshots never change), a form's own answers (given whole, checked against the version they answer, refused in words where they don't fit), a certification's details (driver, tag, vehicle type, prime, subs placed as on a phone, the fix for `SUB_NAME_ALIKE`) and its boxes (shape, sign, feature, a box added or taken off, never the primary). Not corrected: id, project, workflow, kind (made again and the wrong one voided), received time. **`QuarantineReview`** (renumber keeping the phone-made id and photographs; a second copy, nothing made; resolved once). **`BackOfficeRecords`** (a field event, a survey, an incident, a drop-off log with the monitor named and a reason offered for that use; an ROE naming the person, its number off the paper, linking what waited for it; ADR-534 (9)). **`Voids`** (`ticket`, `lift`), **`Acceptances`** (`flag`): the worker then sets a voided ticket's field events `VOID`, removes its lines, clears its flags, keeps the completed record, decision "Voided by <person> (<reason>)."; **a void ticket has no open flag**; an acceptance stays with its flag (a renumber means accepting again); **an acceptance is taken back** with a note (*accept flags*; who and when on its row, history after; one acceptance in force a flag; the worker reads only those in force; ADR-534 (8)); correcting a void ticket's field event brings nothing back. **`QcMarks`**, **`InvoiceLocks`** (`batch`, `lock`, `intoBatch`, `unlock`; grants `QC`, `LOCK_INVOICED`, `UNLOCK_INVOICED`): **only a ticket that is whole, `COMPLETED` and QC Approved locks**; a void one isn't; one that bills nothing is (refusal codes in `InvoiceLocking`, `TicketOnItsOwn`, `BatchName`). **While a ticket is locked, every review service refuses a change to its own records** (`LOCKED_AS_INVOICED`: "Ticket 101001 is locked as invoiced: unlock it first. Nothing was changed."); a service correcting a record several tickets share passes `'PASSED_BY'` and each locked ticket waits, counted; **the database holds a locked ticket's field events (by its number) and the item lines and carried tickets of its locked records, but the two links a number finds** (`certification_id`, `roe_id`); a late field event under the number writes its own lines; the services ask about a lock before they write (ADR-534 (10)). Each act answers `{ record, warnings, queued? }`; its job is queued by the service (Jobs). Endpoints: one per act (`voidTicket`, `acceptFlag`, `correctFieldEvent`, `renumberFieldEvent`, `setQcStatus`, `lockAsInvoiced`, `createInvoiceBatch`, `setLockBatch`, `unlockInvoiced`, `revokeCertification`, …). *Agent defaults, the user's where marked.* [364, 365, 366, 367, 431…433]

### Rules, pricing and the ledger — `adms-ledger-audit`; `spec/RULES.md`, `spec/RATE-SHEET.md` [007, 085, 090, 109, 118, 125, 206, 212, 229, 239, 353…361]
- **The firm types the paper contract's line items as pay items with a rate per prime, and writes rules** (criteria + actions), each naming its contract. **There are no fee kinds:** the # slot keeps a load's lines apart, the site's link to its tipping fee pay item tells a fee line, and the payable type groups lines in exports. **A contract usually prices a line per CY and per ton**, so the prime can use various landfills: the firm enters the pay items it needs and its setup picks; **Open ADMS never chooses.** Read a rate sheet as the choices it allows (`spec/RATE-SHEET.md`, approved). [089, 109, 196…204, 220, 222, 239, 246, 247, 269]
- **Pay items:** a **code** the firm types (setup suggests one from the convention, `spec/CONVENTIONS.md` §5, never forces it), **unique on its project** (the user: "This must be unique per project."), archived ones included, compared exactly as typed; a **description** in the firm's own words (required; nothing reads it; no separate name, no "line number"); a **payable type** (the work, from a firm list seeded from USACE's umbrella debris types; what the monitor's list shows, each once; exported as the type column; **every pay item on every form has one**); **Unit of Measure** (a picked list: **whether a load is weighed is set by it**, no "requires weight" box); a **size band**; the capture settings ("Count is always 1", "GPS required", "Measurement required", "Decimals allowed", "Monitor may mark ineligible", photos required, the quantity method); **its rates, one per prime**. A rate changing from a date is a second pay item with its own code plus *Ticket date* criteria. **A load carries no pay item:** its *Debris type* is the one the monitor picked. [109, 157, 158, 165, 173, 175, 176, 181, 206, 207, 210, 213, 221, 234, 235, 301]
- **The rule builder** (`spec/RULES.md` is the build spec): ticket type → name → **contract** (once) → criteria (operand · operator · value; all must hold; each names the field event it reads; each value picked from a list or typed, RULES §4 says which) → **actions**: *Add transaction #n* (order #, pay item; *Quantity from* on itemised tickets), *Remove transaction #n*, *Void ticket*; Active; Check; Show matches; Reprocess. **Operators:** lists EQUALS · NOT EQUALS · IS ONE OF · IS NOT ONE OF; numbers also BETWEEN (both ends) · AT LEAST · AT MOST · MORE THAN · LESS THAN; dates ON · NOT ON · BETWEEN · ON OR BEFORE · ON OR AFTER; text CONTAINS · STARTS WITH; any IS EMPTY · IS NOT EMPTY. It **warns** on overlapping ranges for the same # and **refuses an exact duplicate** (same form, contract, criteria and actions in any order). **No *Load call* criterion and no *Flag* action** (project settings do that). On a haul-out, *Disposal site* is the FDS, with a criterion for the TDSR it left. **A rule's *Debris type* matches only the exact entry the monitor picked** and reads the collection event's (each property's own on a split). **Mileage is compared in tenths, half up**; text ignoring capitals; *Collection address* is the ticket's address; a unit rate ticket's *Pay item* is the one worked out from its band. [118, 122…125, 128, 130, 131, 135, 164, 226, 244, 301, 354]
- **"Pays when" (setup made easier, model unchanged):** the pay item screen's "Pays when" **writes and keeps its own rule**, one per form it pays on and per contract whose prime has a rate, named "`<code> - <description>`", edited only there; free-standing rules for everything else. A **setup check** lists gaps before the field day (never refuses), and every change shows **what it would change** first. [229, 239, 357]
- **How a ticket is priced** (`packages/domain`: `TicketRules`, `TicketPricing`): a piece at a time (a load or each property, a haul-out or each pile, a unit rate ticket); **every passing rule of its prime's contracts found, every *Add* in # order, then every *Remove*, then any *Void***; the same answer whatever order the rules are in; **criteria read only the ticket**, never another transaction. **A line comparing with something the ticket doesn't have never passes; only IS EMPTY does** (the user). **The # is a slot and the creation order**; the same ticket and rules always give the same transactions. **Each *Add* writes one transaction**; two creates of the same # are flagged (that # only); no rule creating anything is flagged. **The pricing flags** (`NO_PRICING_RULE`, `DUPLICATE_TRANSACTION_NUMBER`, `NO_RATE_FOR_PRIME`, `RATE_TO_BE_NEGOTIATED`, `QUANTITY_MISSING_FOR_PAY_ITEM`, `TIPPING_FEE_RULE_MISSING`, `FILL_WITHOUT_EXPOSED_ROOT_BALL`) are raised only where the rules ran, each keeping its line's # and pay item; a removed fee isn't a missing rule; a rule naming a pay item the project doesn't have throws. **The prime's rate applies** (one pay item, a rate per prime); the transaction records **prime + operating sub** (the lowest-tier sub the certification names, `TicketRead.operatingSubId`). [081, 118, 206, 212, 354, 355, 358]
- **Money (the user):** an amount is rounded **to the cent, half up**, as the quantity kept (four decimals) × the rate; **a crew day by exact division keeps four decimals** (10.25 h ÷ 12 = 0.8542); hours in no step of a crew day paid in steps bill nothing on that line, flagged. **Quantity:** CY = capacity × load call; TN = apportioned net; EA = count; LB = pounds; crew time the highest item's hours through the pay item's conversion (per hour, ÷ day length, or steps); **TBN writes no line until a rate is agreed** (`RATE_TO_BE_NEGOTIATED`; the ticket is `MANUAL_REVIEW` until accepted, KD-72 closed by ADR-373); a pay item with no rate at all is a $0 line, not flagged; one with no rate for the prime is a $0 line, flagged. A ticket under a "not billed" check flag gets no lines (a rule's void still runs); a haul-out dumped at a TDSR skips every rule. More than 12 crew hours a day is flagged. [035, 054, 068, 084, 087, 126, 355]
- **`Transaction`:** a line on exactly one kind of ticket (a completed load's property row, a completed haul-out's pile row, or a unit rate ticket's field event): project, # (`slot`), rule, pay item, contract, prime, operating sub, the unit as it was, quantity, rate, amount, run; the database holds each thing it names to the line's own project. **No mileage on a line** (read from its collection row). **Only the worker's login writes or removes a line; nobody updates one.** [350, 358]
- **Transactions are the current truth: regenerated, never reversed.** The worker writes only what differs: a line standing exactly as the rules give it now is left; one that differs is removed and written again; one no longer given is removed; **the database copies each removed row whole to `AuditRecord` first**. A ticket pending again, voided, or under a "not billed" flag has no lines. **A ticket locked as invoiced is left exactly as it is** and takes or gives up no line (database guards). **A void stays until a person unvoids it, whoever voided it** (the user, ADR-360): a voided ticket is out of every later run. **An errored ticket keeps its lines, flagged** (`NOT_PROCESSED_LINES_STAND`; `NOT_PROCESSED` where it has none). **Only what is active or was changed is worked** (the user's rule for the queue). A rate or rule change regenerates every un-invoiced ticket it affects. [085, 090, 359, 360]
- **`AuditRecord` is append-only, absolutely.** It is the only history. [007, 085]
- **The rules are read one way:** `packages/db`'s `RuleRows`, used by `apps/api`'s `RuleBook` and the worker; `db.$read(work)` is a read-only transaction with no actor. A message names a prime as its contractor's record does. [359]
- **Scale receipts:** only at an FDS, only when the contract asks; hand-transcribed, consumed once; a receipt with two debris types is flagged and its weight unused. **When a load is billed by weight the tower enters the scale weight instead of a load call** (set by the paying pay item's Unit of Measure, never the site); **one quantity, never both**; **no weight-vs-load-call check**. **One weight shared by a tandem** is split by certified capacity (stored apart, summing exactly) and **both tickets are flagged**. [034…038, 069, 165, 175, 221, 223, 227]
- **A contractor user's money:** its own contractor's lines (as the prime, its subs' work among them, or as the sub that did it); **a sub's contractor user reads no rate or amount** (the user, ADR-361). [361]
- **A rule's records:** `Rule` (its project, **one load, haul-out or unit rate form of that project**, a name, **one of the project's contracts** or none, Active with no default, the pay item whose "Pays when" wrote it), `RuleCriterion` (place, criterion, operator, a typed number, date or text), `RuleCriterionPick`, `RuleAction` (*Add transaction* # and pay item with *Quantity from* stated, *Remove transaction* #, *Void ticket*), `RuleActionItem`; every line taken off by archiving. **The database refuses** an operator not its criterion's kind's, a value not its operator's (BETWEEN lower first), a pick that doesn't fill its one column, and **a picked value not the rule's own project's**; a zone is picked by name. **What `spec/RULES.md` §7 calls not valid is saved and never runs** ("Is valid" is no column); an archived pay item, contract or form makes a rule naming it not valid, and the setup check lists it (*agent default*, ADR-357). **In `packages/domain`:** `RuleCriteria` (a form's criteria, each one's kind and operators), `RuleValidity` (§7, every reason in plain words), `ProjectRules.check` (refuses an exact copy, "Not saved: this rule is the same as "…"."; refuses a builder change to a rule a pay item wrote; **warns `RULES_OVERLAP`** when two rules of one form and contract add the same # with nothing apart), `PaysWhen` (one rule per form the pay item pays on and per contract whose prime has a rate, named "`<code> - <description>`"). An *Item* line is one picked item and a number operator on its count. *Agent defaults.* [313, 357]
