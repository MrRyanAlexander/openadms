---
title: Flags reference
description: Every flag Open ADMS can raise - its code, what raises it, the message a reviewer reads and what it does to the money - grouped as the engine checks them.
---

Every flag the engine can raise, as the reviewer reads it. The codes are a closed set in the
database (`FlagCode`): a flag that isn't on this page doesn't exist. Examples come from the example
world; `<…>` in a real message is filled from the ticket.

**Bills** says what an open flag does to the money: **yes**, the ticket bills as if the flag weren't
there; **that line no**, one line bills nothing and the rest bill; **no**, nothing bills until the
ticket is corrected. Accepting a flag never changes what bills. Every message ends "Flagged for
review." unless it says otherwise. See [Flags, never blocks](/concepts/flags/) for how a reviewer
handles them.

:::note[Not a flag]
A second field event of one kind on one ticket is **quarantined** at sync, not flagged. A field
event waiting for its partner, a preload, GPS accuracy, a scale weight against a load call and a
driver's licence are never flagged.
:::

## Between a ticket's field events

| Code                               | Raised when                                                                                                                        | Message                                                                           | Bills                                                           |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `DEBRIS_TYPE_MISMATCH`             | The disposal's debris type isn't the exact entry the collection picked (each property's on a split; a haul-out's two the same way) | "Ticket 101008: debris type mismatch (collection Vegetative, disposal C&D)."      | yes: rules read the collection's                                |
| `CERT_NUMBER_MISMATCH`             | The cert numbers on the ticket's events differ, compared exactly                                                                   | "Ticket 101008: truck number doesn't match (collection 730415, disposal 730416)." | yes, from the certification on the event that took the quantity |
| `DISPOSAL_BEFORE_COLLECTION_ENDED` | The disposal started before its collection ended                                                                                   | "Ticket 101008: disposal started 09:12, before its collection ended 09:40."       | yes                                                             |
| `OVERLAPPING_LOADS`                | Two collections on one certification with overlapping loading times and no disposal between; raised on both tickets                | "Ticket 101031: loading 09:10–09:40 overlaps ticket 101030 on truck 730415."      | yes                                                             |
| `SPLIT_SUFFIX_GAP`                 | A bare collection beside suffixed ones, or a gap in the suffixes: a split load's properties, or a split haul-out's piles           | "Ticket 102001: collections -A and -C, no -B."                                    | yes                                                             |
| `CARRIED_COUNT_MISMATCH`           | On a load that carries tickets, the tower's count differs from the tickets the collection lists                                    | "Ticket 101014: tower counted 3 stumps, the collection lists 4."                  | yes, from the tickets carried                                   |
